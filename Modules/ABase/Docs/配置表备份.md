# 配置表备份 v2.0

> 生成配置表的数据库备份文件，支持模块化配置和分文件输出

## 🆕 新功能特性

### ✨ 核心改进
1. **动态配置**: 支持的配置表不再硬编码，通过配置文件灵活指定
2. **模块扫描**: 自动扫描所有模块的 `configdb配置文件` 来获取备份内容
3. **分文件输出**: 每个模块生成独立的SQL文件，便于管理和分发
4. **灵活配置**: 支持多种表选择方式和条件过滤

### 🎯 配置规则设计
- **表选择**: 支持模型类和表前缀两种选择方式
- **条件过滤**: 支持全表备份或按条件筛选记录
- **字段控制**: 支持排除特定字段或只导出指定字段
- **排序定制**: 可自定义记录排序规则

## 命令概述

**命令名称**: `abase:generate:configdb`

**命令描述**: 生成配置表的数据库备份文件，支持模块化配置和分文件输出

## 使用方法

### 基础用法

```bash
# 备份所有已配置的模块
php artisan abase:generate:configdb

# 备份指定模块
php artisan abase:generate:configdb --module=GameItems

# 列出所有可用的模块配置
php artisan abase:generate:configdb --list

# 指定自定义输出目录
php artisan abase:generate:configdb --output-dir=/path/to/backup
```

### 高级选项

```bash
# 详细输出模式
php artisan abase:generate:configdb -v

# 备份特定模块并显示详细过程
php artisan abase:generate:configdb --module=GameItems -v
```

## 配置文件格式

### 位置
每个模块的配置文件位于：`Modules/{ModuleName}/config/configdb.php`

### 基本结构

```php
<?php

return [
    // 是否启用此模块的配置表备份
    'enabled' => true,

    // 模块显示名称
    'module_name' => 'GameItems',

    // 模块描述
    'description' => '游戏物品模块配置表备份',

    // 备份表配置
    'tables' => [
        // 表配置详细说明见下文
    ],

    // 全局设置
    'global_settings' => [
        'add_module_header' => true,
        'add_statistics' => true,
        'compress_output' => false,
        'default_exclude_columns' => ['laravel_through_key'],
        'default_order_by' => ['id', 'asc'],
    ]
];
```

### 表配置类型

#### 1. 模型类型 (type: model)

通过模型类精确指定表：

```php
'items' => [
    'type' => 'model',
    'model' => \Module\GameItems\Models\Item::class,
    'description' => '游戏物品配置表',
    'condition' => [
        'status' => 'active'           // 只备份激活状态的物品
    ],
    'order_by' => ['id', 'asc'],
    'exclude_columns' => ['laravel_through_key'],
    'only_columns' => [],               // 留空表示包含所有字段
],
```

#### 2. 前缀类型 (type: prefix)

通过表前缀批量指定表：

```php
'game_tables' => [
    'type' => 'prefix',
    'prefix' => 'game_',
    'description' => '游戏模块配置表',
    'exclude_tables' => [
        'game_logs',            // 排除日志表
        'game_temp_data',       // 排除临时数据表
    ],
    'condition' => null,             // 全表备份
    'order_by' => ['id', 'asc'],
    'exclude_columns' => ['created_at', 'updated_at'],
],
```

### 条件配置

支持复杂的WHERE条件：

```php
'condition' => null,                    // 全表备份

'condition' => [                        // 简单条件
    'status' => 'active',
    'is_deleted' => false
],

'condition' => [                        // 复杂条件
    ['created_at', '>=', '2024-01-01'],
    ['status', 'in', ['active', 'pending']],
    ['price', '>', 100]
],
```

## 输出文件

### 文件命名规则
```
{ModuleName}_configdb_{YYYY-MM-DD_HH-mm-ss}.sql
```

### 示例文件名
```
GameItems_configdb_2024-01-15_14-30-25.sql
Game_configdb_2024-01-15_14-30-26.sql
```

### 输出目录
- **默认目录**: `database/sql/modules/`
- **自定义目录**: 通过 `--output-dir` 参数指定

## 实际使用示例

### 1. 游戏物品模块配置

参考文件：`Modules/GameItems/config/configdb.php`

```php
'tables' => [
    // 物品主表 - 只备份激活状态
    'items' => [
        'type' => 'model',
        'model' => \Module\GameItems\Models\Item::class,
        'condition' => ['status' => 'active'],
    ],

    // 使用前缀批量备份物品组相关表
    'item_groups' => [
        'type' => 'prefix',
        'prefix' => 'item_group',
        'exclude_columns' => ['created_at', 'updated_at'],
    ],
],
```

### 2. 游戏核心模块配置

参考文件：`Modules/Game/config/configdb.php`

```php
'tables' => [

        'type' => 'prefix',
        'prefix' => 'game_',
        'exclude_tables' => [
            'game_logs',           // 排除日志表
            'game_user_records',    // 排除用户记录表
        ],
    ],
],
```

## 最佳实践

### 1. 配置文件管理
- 为每个模块创建独立的配置文件
- 使用描述性的配置键名
- 添加详细的注释说明

### 2. 性能优化
- 对于大表，使用条件过滤减少导出数据量
- 排除不必要的字段（如时间戳字段）
- 合理使用前缀配置批量处理相关表

### 3. 安全考虑
- 定期备份配置表数据
- 将备份文件存储在安全位置
- 生成的SQL文件包含敏感数据，请妥善保管

## 注意事项

1. **文件自动生成**: 备份文件由系统自动生成，请勿手动修改
2. **目录权限**: 确保应用有写入输出目录的权限
3. **模块依赖**: 确保相关的模型类可以正确加载
4. **数据一致性**: 建议在系统低峰期执行备份操作
5. **存储空间**: 大量配置数据可能产生较大的备份文件

## 故障排除

### 常见问题

**Q: 命令提示"未找到任何模块配置"**
A: 检查模块目录下是否存在 `config/configdb.php` 文件，并确保 `'enabled' => true`

**Q: 某个模块备份失败**
A: 检查该模块的配置文件语法是否正确，模型类是否存在

**Q: 输出目录创建失败**
A: 检查文件系统权限，确保应用有创建目录的权限

**Q: 备份文件为空**
A: 检查配置的条件设置，可能由于条件过滤导致没有数据

### 调试技巧

1. 使用 `--list` 参数查看所有可用配置
2. 使用 `-v` 参数获取详细的执行过程信息
3. 检查日志文件获取详细错误信息
4. 先备份单个模块进行测试
