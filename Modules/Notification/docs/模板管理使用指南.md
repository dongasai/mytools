## 二、模板配置说明

### 2.1 字段说明

| 字段 | 必填 | 类型 | 说明 | 示例 |
|------|------|------|------|------|
| 模板名称 | 是 | 文本 | 模板显示名称 | "欢迎邮件模板" |
| 通知类型 | 是 | 文本 | 对应的通知类名 | "WelcomeNotification" |
| 适用渠道 | 是 | 选择 | mail/database/sms/push | "database" |
| 通知标题 | 否 | 文本 | 部分渠道需要 | "欢迎加入我们" |
| 通知内容模板 | 是 | 多行文本 | 含变量占位符 | "欢迎 {username} 加入平台" |
| 模板变量说明 | 否 | 标签 | JSON数组格式 | "username,email" |
| 是否启用 | 是 | 开关 | true/false | true |
| 模板描述 | 否 | 多行文本 | 使用说明 | "新用户注册欢迎通知" |

### 2.2 变量占位符

**格式**：`{变量名}`

**示例**：
```text
欢迎 {username} 加入平台！
您的订单 {order_id} 已发货，金额 {amount} 元。
亲爱的 {username}，您的账号 {email} 已创建成功。
```

**变量配置**：
在"模板变量说明"字段输入变量名，多个变量用逗号分隔或使用标签格式：
- 输入：`username` → 添加标签 → 输入 `email` → 添加标签
- 最终保存为：`["username","email"]`

## 四、模板使用流程

### 4.1 通知发送流程

```
1. 业务模块调用
   ModuleNotificationService::send('WelcomeNotification', 'database', $user, $data)

2. 查找激活模板
   TemplateLogic::findActiveTemplate('WelcomeNotification', 'database')

3. 模板渲染
   TemplateLogic::renderTemplate()
   - 替换变量：{username} → $data['username']
   - 返回：['subject' => null, 'content' => '欢迎 张三 加入平台']

4. 创建通知日志
   NotificationLog::create([...])

5. 推送队列发送
   SendNotificationQueue::dispatch()

6. 队列执行
   NotificationService::handleNotification()
   - 发送到 database 渠道
   - 存储 notifications 表

7. 状态更新
   NotificationLogic::markAsSent()
```

### 4.2 测试模板渲染

**使用测试命令**：

```bash
# 测试现有模板渲染
php artisan notification:template

# 输出示例
=== 测试模板渲染 ===
渠道: database
类型: WelcomeNotification

模板信息:
- ID: 1
- 名称: 欢迎通知模板
- 标题: (无)
- 内容: 欢迎 {username} 加入平台！注册时间：{timestamp}...
- 变量: ["username","timestamp"]
- 启用: 是

测试变量: {"username":"测试值_username","timestamp":"测试值_timestamp"}
✓ 模板渲染成功
渲染结果:
- 标题: (无)
- 内容: 欢迎 测试值_username 加入平台！注册时间：测试值_timestamp
```

**创建测试模板**：
```bash
# 如果模板不存在，自动创建测试模板
php artisan notification:template --create
```

## 五、模板管理操作

### 5.1 查看模板列表

**后台操作**：
1. 访问 `/admin/module_notification/notification-templates`
2. 查看所有模板配置
3. 查看模板状态（启用/禁用）
4. 查看模板内容（截断显示前50字符）

**列表字段**：
- ID：模板编号
- 模板名称：显示名称
- 通知类型：关联的通知类
- 适用渠道：mail/database/sms/push
- 标题：通知标题
- 内容：内容模板（截断显示）
- 状态：启用开关
- 操作：编辑/删除按钮

### 5.2 编辑模板

**操作步骤**：
1. 在列表中找到目标模板
2. 点击"编辑"按钮
3. 修改字段内容
4. 点击"提交"保存

**注意事项**：
- notification_type + channel 组合必须唯一
- 修改内容后建议测试渲染效果
- 启用状态影响模板是否生效

### 5.3 启用/禁用模板

**操作方式**：
- 在列表中直接点击"状态"开关
- 或在编辑页面修改"是否启用"字段

**启用状态影响**：
- 启用：模板生效，通知发送时使用
- 禁用：模板不生效，使用通知类默认内容

**建议场景**：
- 新模板先禁用，测试后再启用
- 发现问题时立即禁用
- 维护期间临时禁用

### 5.4 删除模板

**操作步骤**：
1. 在列表中找到目标模板
2. 点击"删除"按钮
3. 确认删除操作

**注意事项**：
- 删除后无法恢复
- 删除模板不影响已发送的通知
- 建议先禁用观察一段时间再删除

## 六、变量配置详解

### 6.1 变量说明字段

**作用**：
- 告知管理员需要提供哪些变量
- 显示在后台模板详情中
- 不强制验证（仅作为说明）

**配置方式**：
- 后台使用标签（tags）格式
- 输入变量名，点击添加
- 多个变量分别添加

**示例**：
```
输入：username → 添加标签
输入：timestamp → 添加标签
结果：["username", "timestamp"]
```

### 6.2 变量使用规范

**变量命名建议**：
- 使用有意义的英文名
- 避免过长名称
- 常见变量：username、email、order_id、timestamp、amount

**变量数量建议**：
- 建议≤5个变量
- 过多变量增加复杂度
- 必需变量优先配置

**变量类型**：
- 字符串：username、email
- 数字：order_id、amount
- 时间：timestamp、delivery_time

### 6.3 变量替换效果

**正常替换**：
```php
// 模板
$content = "欢迎 {username}，订单 {order_id}";

// 变量
$variables = [
    'username' => '张三',
    'order_id' => 'ORD123456',
];

// 结果
$result = "欢迎 张三，订单 ORD123456";
```

**变量缺失**：
```php
// 模板
$content = "欢迎 {username}，订单 {order_id}";

// 只提供 username
$variables = ['username' => '张三'];

// 结果（order_id 未替换）
$result = "欢迎 张三，订单 {order_id}";
```

**验证变量完整性**：
```bash
php artisan notification:template

# 显示缺失变量提示（如果有）
```

## 七、模板优先级机制

### 7.1 模板与默认内容

**优先级规则**：
```
激活模板 > 通知类默认内容
```

**逻辑说明**：
- 模板存在且启用 → 使用模板内容
- 模板不存在或禁用 → 使用通知类 getDefaultContent() 方法的默认内容

**示例流程**：
```php
// 1. 尝试使用模板
$rendered = TemplateLogic::renderTemplate('WelcomeNotification', 'database', $data);

if ($rendered) {
    // 模板生效
    $content = $rendered['content'];
} else {
    // 使用默认内容
    $notification = new WelcomeNotification('张三');
    $default = $notification->getDefaultContent('database', $data);
    $content = $default['message'];
}
```

### 7.2 多渠道模板优先级

**独立性**：
- 每个渠道的模板独立配置
- mail 渠道模板不影响 database 渠道
- 不同渠道可同时有模板或同时无模板

**示例**：
```
WelcomeNotification + mail 渠道 → 有模板 → 使用模板内容
WelcomeNotification + database 渠道 → 无模板 → 使用默认内容
WelcomeNotification + sms 渠道 → 有模板（禁用） → 使用默认内容
```

## 八、常见问题处理

### 8.1 模板不生效

**可能原因**：
1. 模板未启用（is_active = false）
2. notification_type 与通知类名称不匹配
3. channel 与发送渠道不匹配
4. 模板配置错误（数据库约束冲突）

**排查方法**：
```bash
# 查看模板配置
php artisan tinker --execute="
\$template = NotificationTemplate::where('notification_type', 'WelcomeNotification')
    ->where('channel', 'database')
    ->first();
print_r(\$template->toArray());
"

# 检查启用状态
php artisan tinker --execute="
\$template = NotificationTemplate::find(1);
echo '启用状态: ' . (\$template->is_active ? '是' : '否');
"
```

**解决方法**：
- 检查并修正 notification_type 和 channel 配置
- 启用模板（设置 is_active = true）
- 删除冲突模板，重新创建

### 8.2 变量未替换

**可能原因**：
- 提供的变量数组中缺少对应变量
- 变量名拼写错误
- 占位符格式错误（不是 `{变量名}` 格式）

**排查方法**：
```php
// 检查变量完整性
$template = NotificationTemplate::find(1);
$variables = ['username' => '张三'];

$missing = TemplateLogic::validateVariables($template, $variables);
// 返回缺失变量：['timestamp', 'email']
```

**解决方法**：
- 检查模板内容中的占位符
- 确保提供所有必需变量
- 修正变量名拼写

### 8.3 模板渲染失败

**可能原因**：
- 模板不存在（数据库无记录）
- 模板被禁用（is_active = false）
- notification_type + channel 组合错误

**排查方法**：
```bash
# 测试模板渲染
php artisan notification:template --type=WelcomeNotification --channel=database

# 输出：
模板不存在
提示: 使用 --create 选项自动创建测试模板
```

**解决方法**：
- 创建模板：`php artisan notification:template --create`
- 后台手动创建模板
- 检查模板配置是否正确

## 十、进阶技巧

### 10.1 多模板管理

**场景**：同一通知类型在不同渠道有不同模板

**管理策略**：
```
WelcomeNotification:
  - mail 渠道 → "欢迎邮件模板"（未实现，禁用）
  - database 渠道 → "欢迎通知模板"（启用）
  - sms 渠道 → "欢迎短信模板"（未实现，禁用）
```

**优势**：
- 灵活配置不同渠道内容
- 针对不同渠道特点设计
- 独立管理和维护

### 10.2 模板继承与覆盖

**概念**：
- 通知类定义默认内容
- 模板可覆盖默认内容
- 模板禁用时回归默认内容

**应用场景**：
- 开发阶段：使用默认内容快速测试
- 生产阶段：启用模板动态配置
- 维护阶段：禁用模板临时使用默认内容

### 10.3 模板数据分析（可选）

**统计模板使用情况**：
```sql
-- 查看模板对应的通知发送次数
SELECT
    t.name,
    t.notification_type,
    t.channel,
    COUNT(l.id) as send_count
FROM notification_templates t
LEFT JOIN notification_logs l
    ON l.notification_type = t.notification_type
    AND l.channel = t.channel
GROUP BY t.id
ORDER BY send_count DESC;
```

**分析结果**：
- 了解模板使用频率
- 发现未使用的模板
- 优化模板配置

## 十一、API 集成

- channel 设置为通知类支持的渠道
- 创建对应模板配置
