## 一、模板系统概述

### 1.1 设计目标

通知模板系统提供动态配置通知内容的能力，支持：
- 多渠道模板配置（mail/database/sms/push）
- 模板变量替换（`{变量名}` 格式）
- 模板与通知类关联
- 模板覆盖默认内容

### 1.2 核心概念

**通知类**：
- 每个通知由一个单独的类表示（如 WelcomeNotification）
- 提供默认通知内容
- 可被模板覆盖

**通知模板**：
- 关联通知类型（notification_type）和渠道（channel）
- 定义标题（subject）和内容（content）
- 配置变量说明（variables）

**模板渲染**：
- 查找激活模板 → 变量替换 → 返回渲染内容
- 模板不存在时使用通知类的默认内容

## 二、数据结构设计

### 2.1 数据库表结构

**notification_templates 表**：

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| id | int | 主键 | 1 |
| name | string | 模板名称 | "欢迎邮件模板" |
| notification_type | string | 通知类型 | "WelcomeNotification" |
| channel | string | 适用渠道 | "mail" / "database" |
| subject | string|null | 通知标题 | "欢迎加入我们" |
| content | string | 通知内容模板 | "亲爱的 {username}，欢迎加入！" |
| variables | array|null | 模板变量说明 | ["username", "email"] |
| is_active | boolean | 是否启用 | true |
| description | string|null | 模板描述 | "新用户注册欢迎邮件" |
| created_at | timestamp | 创建时间 | 2026-06-27 19:00:00 |
| updated_at | timestamp | 更新时间 | 2026-06-27 19:00:00 |

**唯一约束**：
```sql
UNIQUE KEY unique_template (notification_type, channel)
```

**设计说明**：
- 同一通知类型+渠道只能有一个模板
- 启用状态控制模板是否生效
- variables 字段存储数组（JSON格式）

### 2.2 Model 层设计

**NotificationTemplate Model**：
- 表名：`notification_templates`
- 可填充字段：name、notification_type、channel、subject、content、variables、is_active、description
- 类型转换：variables → array、is_active → boolean

**职责边界**：
- Model 层只负责数据结构和属性定义
- 不包含业务逻辑（查询、渲染在 Logic 层）

## 三、架构分层设计

### 3.1 分层架构

```
NotificationTemplate Model (数据层)
    ↓ 定义数据结构
TemplateLogic (逻辑层)
    ↓ 提供渲染和查询方法
ModuleNotificationService (服务层)
    ↓ 协调模板渲染和通知发送
NotificationLog Model (记录层)
    ↓ 记录通知发送历史
```

### 3.2 TemplateLogic 设计

**职责**：
- 查找激活模板（findActiveTemplate）
- 渲染模板内容（renderTemplateContent）
- 渲染模板标题（renderTemplateSubject）
- 统一渲染入口（renderTemplate）
- 验证变量完整性（validateVariables）

**设计特点**：
- 全静态方法
- 无状态设计
- 高性能
- 易于测试

**核心方法**：

```php
// 1. 查找激活模板
public static function findActiveTemplate(
    string $notificationType,
    string $channel
): ?NotificationTemplate

// 2. 渲染模板内容
public static function renderTemplateContent(
    NotificationTemplate $template,
    array $variables
): string

// 3. 渲染模板标题
public static function renderTemplateSubject(
    NotificationTemplate $template,
    array $variables
): ?string

// 4. 统一渲染入口
public static function renderTemplate(
    string $notificationType,
    string $channel,
    array $variables
): ?array  // 返回 ['subject' => ..., 'content' => ...]

// 5. 验证变量完整性
public static function validateVariables(
    NotificationTemplate $template,
    array $providedVariables
): array  // 返回缺失变量列表
```

## 四、模板渲染机制

### 4.1 渲染流程

```
发送通知请求
    ↓
ModuleNotificationService::send()
    ↓
TemplateLogic::renderTemplate()
    ↓
1. 查找激活模板
   - notification_type = 'WelcomeNotification'
   - channel = 'database'
   - is_active = true
    ↓
2. 模板存在？
   - YES: 使用模板渲染
   - NO: 使用通知类默认内容
    ↓
3. 变量替换
   - 模板: "欢迎 {username} 加入平台"
   - 变量: ['username' => '张三']
   - 结果: "欢迎 张三 加入平台"
    ↓
4. 返回渲染结果
   ['subject' => '欢迎加入', 'content' => '欢迎 张三 加入平台']
    ↓
5. 创建通知日志
    ↓
6. 推送队列发送
```

### 4.2 变量替换规则

**占位符格式**：`{变量名}`

**替换示例**：
```php
// 模板内容
$content = "亲爱的 {username}，您的订单 {order_id} 已发货";

// 提供变量
$variables = [
    'username' => '张三',
    'order_id' => 'ORD123456',
];

// 渲染结果
$result = "亲爱的 张三，您的订单 ORD123456 已发货";
```

**替换逻辑**：
```php
foreach ($variables as $key => $value) {
    $placeholder = '{' . $key . '}';
    $content = str_replace($placeholder, (string) $value, $content);
}
```

### 4.3 模板覆盖机制

**优先级**：
```
激活模板 > 通知类默认内容
```

**逻辑实现**：
```php
// 1. 尝试使用模板
$rendered = TemplateLogic::renderTemplate($type, $channel, $data);

if ($rendered) {
    // 模板存在且启用
    $subject = $rendered['subject'];
    $content = $rendered['content'];
} else {
    // 模板不存在，使用通知类默认内容
    $notification = new WelcomeNotification($username);
    $default = $notification->getDefaultContent($channel, $data);
    $subject = $default['subject'] ?? null;
    $content = $default['content'] ?? '';
}
```

**好处**：
- 灵活性：可动态修改通知内容
- 兜底机制：模板不存在时使用默认内容
- 无需修改代码：通过后台配置即可调整

## 五、多渠道模板支持

### 5.1 渠道模板配置

**同一通知类型可有多个渠道模板**：

```sql
-- WelcomeNotification 的 mail 渠道模板
notification_type: WelcomeNotification
channel: mail
subject: 欢迎加入我们
content: 亲爱的 {username}，欢迎注册...

-- WelcomeNotification 的 database 渠道模板
notification_type: WelcomeNotification
channel: database
subject: null
content: 欢迎 {username} 加入平台

-- WelcomeNotification 的 sms 渠道模板
notification_type: WelcomeNotification
channel: sms
subject: null
content: 【平台】{username}，欢迎加入！
```

**设计说明**：
- 不同渠道可能有不同的内容格式
- mail 渠道通常需要 subject（邮件主题）
- database/sms 渠道可能不需要 subject
- 每个渠道独立配置，互不影响

### 5.2 渠道选择逻辑

**发送流程**：
```php
// 1. 确定通知类型和渠道
$notificationType = 'WelcomeNotification';
$channel = 'database';  // 或 'mail', 'sms', 'push'

// 2. 查找对应渠道的模板
$template = TemplateLogic::findActiveTemplate($notificationType, $channel);

// 3. 渲染模板
$rendered = TemplateLogic::renderTemplate($notificationType, $channel, $variables);

// 4. 发送到指定渠道
NotificationService::sendByChannel($channel, $data);
```

## 六、变量验证机制

### 6.1 变量完整性检查

**目的**：
- 确保提供所有必需变量
- 防止模板渲染出现未替换的占位符
- 提供友好的错误提示

**验证方法**：
```php
$template = NotificationTemplate::find(1);
$providedVariables = ['username' => '张三'];

// 检查变量完整性
$missingVariables = TemplateLogic::validateVariables($template, $providedVariables);

// 返回缺失变量
// ['email', 'timestamp']
```

**建议使用场景**：
- 后台模板配置时验证变量配置
- 通知发送前验证数据完整性
- 提供用户友好的错误提示

### 6.2 变量配置说明

**variables 字段设计**：
- 存储数组：`["username", "email", "timestamp"]`
- 仅作为说明字段，不强制验证
- 后台显示：帮助管理员了解需要的变量

**示例配置**：
```json
{
    "name": "欢迎邮件模板",
    "notification_type": "WelcomeNotification",
    "channel": "mail",
    "subject": "欢迎加入我们",
    "content": "亲爱的 {username}，您的账号 {email} 已创建成功",
```

## 十、错误处理设计

### 10.1 模板不存在

**处理方式**：
- 使用通知类的默认内容
- 不抛出异常（静默降级）
- 记录日志（可选）

```php
$rendered = TemplateLogic::renderTemplate($type, $channel, $variables);

if (!$rendered) {
    // 使用默认内容
    $notification = new $type($data);
    $default = $notification->getDefaultContent($channel, $variables);
}
```

### 10.2 变量缺失

**处理方式**：
- 不抛出异常
- 未替换的占位符保留 `{变量名}`
- 提供验证方法供开发者检查

```php
// 模板内容
$content = "欢迎 {username}，订单 {order_id}";

// 只提供 username
$variables = ['username' => '张三'];

// 渲染结果
$result = "欢迎 张三，订单 {order_id}";  // order_id 未替换
```

### 10.3 模板配置错误

**后台验证**：
- notification_type + channel 唯一性检查
- 变量配置合法性检查
- 启用状态逻辑检查

## 十一、最佳实践建议

### 11.1 模板命名规范

**建议格式**：
- 中文命名：`"欢迎邮件模板"`、`"订单通知模板"`
- 包含用途：`"订单发货邮件模板"`
- 易于理解：避免过于技术化的名称

**建议实践**：
- 配置必需变量
- 提供变量说明（description字段）
- 避免过多变量（建议≤5个）
- 变量名使用有意义的英文（username、order_id）

### 11.3 模板维护建议

**定期维护**：
- 定期检查模板启用状态
- 清理过期的模板配置
- 更新变量配置说明

**版本管理**：
