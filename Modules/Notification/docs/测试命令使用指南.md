## 命令概述

Notification 模块提供三个独立的测试命令，职责单一，功能清晰：

- `notification:send`：测试通知发送功能（单个、批量、统计）
- `notification:template`：测试模板渲染功能
- `notification:status`：测试状态更新功能

---

## 一、发送测试命令

### 基本用法

```bash
php artisan notification:send <action> [options]
```

**必填参数**：
- `action`：测试动作，支持以下选项：
  - `single`：测试单个通知发送
  - `batch`：测试批量通知发送
  - `stats`：查看统计信息

**可选选项**：
- `--channel=mail`：通知渠道（mail|sms|push|database）
- `--type=WelcomeNotification`：通知类型（默认使用已存在的欢迎通知类）
- `--user-id=*`：指定用户ID（单个发送时指定）
- `--count=1`：批量发送数量
- `--force`：强制执行不询问确认

## 二、模板测试命令

### 基本用法

```bash
php artisan notification:template [options]
```

**可选选项**：
- `--channel=mail`：通知渠道（mail|sms|push|database）
- `--type=WelcomeNotification`：通知类型
- `--create`：创建测试模板（如果不存在）

### 2.1 测试模板渲染

```bash
php artisan notification:template --type=WelcomeNotification --channel=mail
```

**前提条件**：
- 数据库中必须存在对应的模板记录
- 模板的 notification_type 和 channel 必须匹配参数
- 模板的 is_active 必须为 true

**输出示例**：
```

类型: WelcomeNotification

模板信息:
- ID: 1
- 名称: welcome_mail
- 标题: 欢迎加入
- 内容: 欢迎 {username} 加入我们的平台！...
- 变量: ["username"]
- 启用: 是

测试变量: {"username":"测试值_username"}
✓ 模板渲染成功
渲染结果:
- 标题: 欢迎加入
- 内容: 欢迎 测试值_username 加入我们的平台！
```

### 2.2 自动创建测试模板

如果模板不存在，可以使用 `--create` 选项自动创建：

## 三、状态测试命令

### 基本用法

```bash
php artisan notification:status [options]
```

**可选选项**：
- `--log-id=*`：日志ID（可选，不指定则自动查找pending日志）
- `--force`：强制执行不询问确认

### 3.1 测试状态更新流程

```bash
php artisan notification:status --force
```

**功能说明**：
- 自动查找最近的 pending 状态日志
- 测试完整的状态更新流程：
  1. `markAsSending`：标记为发送中（sending）
  2. `markAsSent`：标记为已发送（sent），记录发送时间
  3. `incrementRetry`：增加重试次数（retry_count）
  4. `markAsFailed`：标记为失败（failed），记录错误信息

## 常见用途

### 1. 快速验证通知系统

```bash
# 发送一个测试通知
php artisan notification:send single --force

# 查看统计数据
php artisan notification:send stats
```

### 2. 测试模板配置

```bash
# 创建并测试模板
php artisan notification:template --create

# 测试特定渠道模板
php artisan notification:template --channel=sms
```

### 3. 批量测试性能

```bash
# 批量发送50个通知
php artisan notification:send batch --count=50 --force

# 查看统计
php artisan notification:send stats
```

### 4. 状态管理验证

```bash
# 创建测试通知
php artisan notification:send single --force

# 测试状态更新
php artisan notification:status --force
```

### 5. 清理积压通知

```bash
# 预览 pending 状态的 mail 渠道通知
php artisan notification:clean --status=pending --channel=mail --dry-run

# 将 pending 标记为 failed（不删除）
php artisan notification:clean --status=pending --channel=mail --mark-failed --force

# 删除30天前的失败通知
php artisan notification:clean --status=failed --older-than=30 --force

# 清理所有 mail 渠道的失败通知
php artisan notification:clean --channel=mail --status=failed --force
```

## 数据清理

### 测试数据清理

测试命令会创建真实的数据库记录，测试完成后可手动清理：

```bash
# 清理测试通知日志
php artisan notification:clean --type=WelcomeNotification --older-than=1 --force

# 清理测试用户（需要tinker）
php artisan tinker --execute="User1::where('email', 'like', 'test-notification%')->delete()"

# 清理测试模板（如果创建了测试模板）
php artisan tinker --execute="NotificationTemplate::where('name', 'like', '测试模板-%')->delete()"
```

### 积压通知清理

当渠道未实现或有大量待发送通知时，使用清理命令：

```bash
# 预览模式（安全）
php artisan notification:clean --status=pending --dry-run

# 标记为失败（保留记录）
php artisan notification:clean --status=pending --mark-failed --force

# 直接删除（谨慎使用）
php artisan notification:clean --status=pending --force
```

### 定期维护

建议定期清理旧数据：

```bash
# 清理60天前的已发送通知
php artisan notification:clean --status=sent --older-than=60 --force

# 清理90天前的失败通知
php artisan notification:clean --status=failed --older-than=90 --force
```

## 注意事项

1. **真实数据写入**：命令会真实写入数据库，不是模拟测试
2. **队列依赖**：通知发送依赖队列系统，需启动 queue:work
3. **模板前提**：template 测试需要数据库中已存在对应模板（或使用 --create）
4. **默认通知类型**：默认使用 WelcomeNotification（已存在的通知类）
5. **用户依赖**：send 测试依赖 User1 模块（可修改代码适配其他用户模型）
6. **渠道限制**：实际发送需要配置对应的渠道服务（邮件/短信/推送）
7. **数据清理**：测试完成后记得清理测试数据，避免污染数据库
