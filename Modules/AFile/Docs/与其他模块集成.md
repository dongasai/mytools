# 文件模块与其他模块集成

## 1. 概述

文件模块作为系统中的基础服务模块，提供了文件和图片的上传、存储、管理和访问功能，需要与系统中的其他模块进行集成，以支持各种业务场景下的文件处理需求。本文档描述了文件模块与其他模块的集成方案。

## 2. 集成方式

### 2.1 使用 ModuleFileService(推荐)

其他模块可以使用 `ModuleFileService` 静态方法类，这是专门为跨模块对接设计的简化接口：

```php
use Modules\AFile\Services\ModuleFileService;

// 上传图片并标记使用(一步完成，推荐)
$image = ModuleFileService::uploadImageAndMark(
    $request->file('image'),
    $userId,
    false,
    'novel_chapter_cover',
    $chapterId
);

// 获取图片URL
$imageUrl = ModuleFileService::getImageUrl($imageId);

// 取消关联并删除图片(彻底清理)
ModuleFileService::unlinkAndDeleteImage($imageId);

// 批量操作
ModuleFileService::batchUnlinkAndDeleteImages([$imageId1, $imageId2, $imageId3]);
```

**优势**:
- 全静态方法，无需实例化
- 自动异常捕获和日志记录
- 提供一步完成方法，简化流程
- 批量操作优化性能

详细使用说明请查看 [ModuleFileService使用指南](ModuleFileService使用指南.md)。

### 2.2 使用服务类(灵活方式)

其他模块也可以直接通过调用文件模块提供的服务类来使用文件模块的功能：

```php
// 使用文件服务
$fileService = new \Modules\AFile\Services\FileService();
$fileUrl = $fileService->getFileUrl($fileId);

// 使用图片服务
$imgService = new \Modules\AFile\Services\ImgService();
$imageUrl = $imgService->getPicUrl4Id($imageId);

// 使用临时文件服务
$temporaryService = new \Modules\AFile\Services\TemporaryService();
$tempFilePath = $temporaryService->save('txt', 'Hello, World!');
```

**适用场景**:
- 需要更灵活的异常处理
- AFile 模块内部使用
- 需要直接访问底层服务

### 2.2 事件监听

其他模块可以监听文件模块触发的事件，以响应文件操作：

```php
// 在其他模块的服务提供者中
protected $listen = [
    \Modules\AFile\Events\FileUploadedEvent::class => [
        \Module\OtherModule\Listeners\HandleFileUploadedListener::class,
    ],
    \Modules\AFile\Events\ImageUploadedEvent::class => [
        \Module\OtherModule\Listeners\HandleImageUploadedListener::class,
    ],
];
```

### 2.3 模型关联

其他模块的模型可以与文件模块的模型建立关联，以实现文件与业务数据的关联：

```php
// 在其他模块的模型中
public function files()
{
    return $this->morphMany(\Modules\AFile\Models\FileFile::class, 're', 're_type', 're_id');
}

public function images()
{
    return $this->morphMany(\Modules\AFile\Models\FileImg::class, 're', 're_type', 're_id');
}
```

## 3. 文件业务关联机制

### 3.1 关联设计

文件模块通过 `re_type` 和 `re_id` 字段实现文件与业务数据的关联:

- **re_type**: 关联类型,标识业务用途
  - 命名规范: `模块名_实体名_用途`
  - 示例: `novel_chapter_cover`(小说章节封面)、`user_avatar`(用户头像)
- **re_id**: 关联业务ID
  - 对应业务实体的主键ID

### 3.2 文件状态管理

文件模块通过 `status` 字段管理文件生命周期:

- **normal**: 正常状态,刚上传未关联业务
- **linked**: 已关联状态,已标记被业务使用
- **dangling**: 悬空状态,孤儿文件(业务已删除但文件未删除)

#### 标记使用流程

```php
// 业务创建完成后,标记文件为已使用
$fileService = new \Modules\AFile\Services\FileService();
$fileService->markFileAsUsed($fileId);

// 批量标记(避免N+1查询)
$fileService->batchMarkAsUsed([$fileId1, $fileId2, $fileId3]);
```

**关键点**:
- 仅当 `status='normal'` 且 `used_at=null` 时才更新
- 防止重复标记
- 记录使用时间 `used_at`
- 触发事件通知其他模块

#### 取消关联流程

```php
// 业务删除时,取消文件关联(不删除文件,标记为悬空状态)
$fileService = new \Modules\AFile\Services\FileService();
$fileService->unlinkFile($fileId, true);  // 标记为 dangling 状态

// 业务删除时,取消文件关联并删除文件
$fileService->unlinkAndDeleteFile($fileId);

// 批量取消文件关联
$fileService->batchUnlinkFiles([$fileId1, $fileId2, $fileId3], true);

// 批量取消关联并删除文件
$fileService->batchUnlinkAndDeleteFiles([$fileId1, $fileId2, $fileId3]);
```

**关键点**:
- `unlinkFile()`: 解除关联但不删除文件,可选择是否标记为 `dangling` 状态
- `unlinkAndDeleteFile()`: 解除关联并删除文件,彻底清理
- `batchUnlinkFiles()`: 批量解除关联,避免N+1查询
- `dangling` 状态用于标识孤儿文件,便于后续清理或重新关联

### 3.3 业务关联模式

#### 模式1: 上传时直接关联(推荐)

适用于上传时已知业务ID的场景:

```php
$imgService = new \Modules\AFile\Services\ImgService();
$image = $imgService->uploadImg($file, $userId, false, 'novel_chapter_cover', $chapterId);

// 文件创建时即设置 re_type 和 re_id
// 状态仍为 'normal',需后续标记为 'linked'
$fileService = new \Modules\AFile\Services\FileService();
$fileService->markImageAsUsed($image->id);
```

#### 模式2: 上传后关联(两步法)

适用于业务ID未知的场景:

```php
// 步骤1: 上传文件(不关联)
$imgService = new \Modules\AFile\Services\ImgService();
$image = $imgService->uploadImg($file, $userId, false);
// re_type='', re_id=0

// 步骤2: 业务创建后关联并标记
$chapter = Chapter::create([...]);
$image->re_type = 'novel_chapter_cover';
$image->re_id = $chapter->id;
$image->save();

$fileService = new \Modules\AFile\Services\FileService();
$fileService->markImageAsUsed($image->id);
```

## 4. 与具体模块的集成

### 4.1 与用户模块集成

用户模块可以使用文件模块来管理用户头像和用户上传的文件:

```php
// 上传用户头像
$imgService = new \Modules\AFile\Services\ImgService();
$avatar = $imgService->uploadImg($request->file('avatar'), $userId, false, 'user_avatar', $userId);

// 标记图片为已使用
$fileService = new \Modules\AFile\Services\FileService();
$fileService->markImageAsUsed($avatar->id);

// 获取用户头像URL
$avatarUrl = $imgService->getPicUrl4Id($avatar->id);
```

### 4.2 与小说模块集成

小说模块可以使用文件模块来管理小说章节封面和内容图片:

```php
// 上传章节封面(上传时直接关联)
$chapter = Chapter::create([...]);
$imgService = new \Modules\AFile\Services\ImgService();
$coverImage = $imgService->uploadImg(
    $request->file('cover'),
    $userId,
    false,
    'novel_chapter_cover',
    $chapter->id
);

// 标记图片为已使用
$fileService = new \Modules\AFile\Services\FileService();
$fileService->markImageAsUsed($coverImage->id);

// 批量上传章节内容图片
$contentImages = [];
foreach ($request->file('content_images') as $image) {
    $contentImages[] = $imgService->uploadImg($image, $userId, false, 'novel_chapter_content', $chapter->id);
}

// 批量标记
$fileIds = array_map(function($img) { return $img->id; }, $contentImages);
$fileService->batchMarkAsUsed($fileIds);
```

### 4.3 与文章模块集成

文章模块可以使用文件模块来管理文章中的图片和附件:

```php
// 上传文章图片(两步法)
$imgService = new \Modules\AFile\Services\ImgService();
$image = $imgService->uploadImg($request->file('image'), $userId, false);

// 创建文章记录
$article = Article::create([...]);

// 关联图片并标记使用
$image->re_type = 'article_image';
$image->re_id = $article->id;
$image->save();
$fileService->markImageAsUsed($image->id);

// 上传文章附件
$fileService = new \Modules\AFile\Services\FileService();
$file = $fileService->uploadFile($request->file('attachment'), $userId, 'article_attachment', $articleId);
$fileService->markFileAsUsed($file->id);
```

### 4.4 与商品模块集成

商品模块可以使用文件模块来管理商品图片和商品详情图:

```php
// 上传商品主图(上传时直接关联)
$product = Product::create([...]);
$imgService = new \Modules\AFile\Services\ImgService();
$mainImage = $imgService->uploadImg(
    $request->file('main_image'),
    $userId,
    false,
    'product_main_image',
    $product->id
);
$fileService->markImageAsUsed($mainImage->id);

// 批量上传商品详情图
$detailImages = [];
foreach ($request->file('detail_images') as $image) {
    $detailImages[] = $imgService->uploadImg($image, $userId, false, 'product_detail_image', $productId);
}

// 批量标记
$imageIds = array_map(function($img) { return $img->id; }, $detailImages);
foreach ($imageIds as $imageId) {
    $fileService->markImageAsUsed($imageId);
}
```

### 4.5 与消息模块集成

消息模块可以使用文件模块来管理消息中的图片和附件:


## 5. 集成注意事项

### 5.1 关联类型命名规范

在使用文件模块的关联功能时，关联类型（re_type）的命名应遵循以下规范：

- 使用小写字母和下划线
- 格式为：`模块名_实体名_用途`
- 例如：`user_avatar`、`article_image`、`product_main_image`、`novel_chapter_cover`

### 5.2 文件状态管理规范

在集成过程中，需要注意文件的状态管理：

- **上传后标记**: 文件上传后必须调用 `markFileAsUsed()` 或 `markImageAsUsed()` 标记为已使用
- **批量标记**: 多个文件使用 `batchMarkAsUsed()` 提高性能
- **状态验证**: 仅当 `status='normal'` 且 `used_at=null` 时才能标记,防止重复标记
- **生命周期**: 业务删除时应同步删除关联文件,避免产生孤儿文件(dangling状态)

### 5.3 文件权限控制

在集成过程中，需要注意文件的权限控制：

- 公开文件：可以直接通过URL访问，适用于公开内容，如文章图片、商品图片等
- 私有文件：需要通过授权才能访问，适用于敏感内容，如用户上传的私密文件等

### 5.4 文件生命周期管理

在集成过程中，需要注意文件的生命周期管理：

- **创建**：在创建业务数据时，同时上传并关联文件，然后标记为已使用
- **更新**：在更新业务数据时，可能需要更新关联的文件(删除旧文件、上传新文件、重新标记)
- **删除**：在删除业务数据时，应同时删除关联的文件，避免产生孤立文件(dangling状态)

### 5.5 性能优化

在集成过程中，需要注意性能优化：

- **批量标记**：使用 `batchMarkAsUsed()` 批量标记文件，避免N+1查询
- **延迟加载**：使用延迟加载关联，避免不必要的查询
- **预加载**：在需要批量获取文件信息时，使用预加载关联，减少查询次数
- **缓存**：对频繁访问的文件URL进行缓存，减少数据库查询
