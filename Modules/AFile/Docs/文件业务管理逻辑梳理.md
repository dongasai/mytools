# AFile 模块文件业务管理逻辑梳理

## 1. 模块概述

AFile 模块是项目的基础文件管理模块,提供文件和图片的上传、存储、管理、访问功能。采用单模块全栈架构,包含完整的业务逻辑和多种入口形式(DcatAdmin/Api)。

### 核心能力
- 文件上传与存储
- 图片上传与处理(自动转webp)
- 文件状态管理(normal → linked → dangling)
- 存储配置管理(多环境、多驱动)
- 临时文件管理
- 事件驱动架构

## 2. 架构分层

### 2.1 Models层(数据结构)

| Model | 表名 | 说明 |
|-------|------|------|
| FileFile | file_files | 普通文件表 |
| FileImg | file_imgs | 图片文件表 |
| FileStorageConfig | file_storage_configs | 存储配置表 |
| FileStorageConfigHistory | file_storage_config_histories | 配置历史表 |
| FileTemplate | file_template | 文件模板表 |

**核心字段**:
- `storage_disk`: 存储磁盘名称
- `path`: 文件存储路径
- `user_id`: 上传用户ID
- `re_type`: 关联类型(业务标识)
- `re_id`: 关联业务ID
- `status`: 文件状态(normal/linked/dangling)
- `used_at`: 使用时间
- `dangling_at`: 悬空时间

### 2.2 Services层(业务协调)

| Service | 职责 |
|---------|------|
| FileService | 文件上传、下载、删除、标记使用 |
| ImgService | 图片URL获取、图片下载 |
| UploadService | 图片上传(转webp处理) |
| TemporaryService | 临时文件保存、获取、删除 |
| StorageConfigService | 存储配置管理、缓存、历史记录 |

**特点**:
- 协调Logics和Models
- 参数由Controller显性传入
- **禁止读取HTTP/session**
- 优先静态方法(部分实例方法因状态管理需求)

### 2.3 Logics层(具体逻辑)

| Logic | 职责 |
|-------|------|
| FileLogic | 文件上传、下载、删除的具体逻辑 |
| DirLogic | 用户目录生成规则 |
| FileBaseLogic | 文件基础逻辑(抽象) |

**特点**:
- 无状态静态方法
- 高性能操作
- 实际执行文件操作

### 2.4 Events层(事件驱动)

| Event | 触发时机 | 用途 |
|-------|---------|------|
| FileUploadedEvent | 文件上传后 | 模块间通知 |

## 3. 核心业务流程

### 3.1 文件上传流程

```
Controller → FileService.uploadFile()
  ↓
FileLogic.uploadFile()
  ↓
DirLogic.getDir(userId) → 生成用户目录
  ↓
StorageConfigService.getDefaultDisk() → 获取默认存储配置
  ↓
动态注册磁盘配置 → config(["filesystems.disks.{$diskName}" => $config])
  ↓
Storage::disk($diskName)->putFileAs() → 存储文件
  ↓
FileFile Model 创建 → 保存文件记录(status='normal')
  ↓
FileUploadedEvent::dispatch($fileModel) → 触发上传事件
```

**关键点**:
1. 从数据库动态获取存储配置(支持多环境)
2. 动态注册磁盘配置,确保配置可用
3. 文件初始状态为 `normal`(未关联)
4. 立即触发事件通知其他模块

### 3.2 图片上传流程(特殊处理)

```
Controller → FileService.uploadImage()
  ↓
FileLogic.uploadImage()
  ↓
UploadService.uploadImg()
  ↓
DirLogic.getDir(userId) → 生成用户目录
  ↓
Intervention Image 处理 → 自动转webp格式
  ↓
获取图片尺寸 → width、height
  ↓
Storage::disk($disk)->put() → 存储webp文件
  ↓
FileImg Model 创建 → 保存图片记录(status='normal', private标志)
  ↓
ImageUploadedEvent::dispatch($fileImg) → 触发上传事件
```

**关键点**:
1. 图片自动转换为webp格式(节省空间)
2. 记录图片尺寸(width/height)
3. 支持私有图片(private字段)
4. 使用StorageConfig::getStorage()获取存储

### 3.3 文件状态管理流程(核心业务)

#### 状态定义
- **normal**: 正常状态,刚上传未关联业务
- **linked**: 已关联状态,已标记被业务使用
- **dangling**: 悬空状态,孤儿文件(业务已删除但文件未删除)

#### 标记使用流程
```
业务创建完成 → FileService.markFileAsUsed($fileId)
  ↓
DB::table('file_files')
  → where('status', 'normal')
  → whereNull('used_at')
  → update(['status' => 'linked', 'used_at' => now()])
  ↓
MarkFileUsedEvent::dispatch($fileId) → 触发使用事件
```

**关键点**:
1. 仅当 `status='normal'` 且 `used_at=null` 时才更新
2. 防止重复标记
3. 记录使用时间 `used_at`
4. 事件在事务外触发

#### 批量标记
```
FileService.batchMarkAsUsed(array $fileIds)
  ↓
DB::table('file_files')
  → whereIn('id', $fileIds)
  → where('status', 'normal')
  → whereNull('used_at')
  → update(['status' => 'linked', 'used_at' => now()])
  ↓
foreach ($fileIds as $fileId) {
    MarkFileUsedEvent::dispatch($fileId)
}
```

**优势**: 避免N+1查询,批量更新性能更好

### 3.4 文件访问流程

#### 普通文件下载
```
请求: /api/v1/files/{fileId}/download
  ↓
FileService.downloadFile($fileId)
  ↓
FileLogic.downloadFile($fileId)
  ↓
FileFile::find($fileId) → 查找文件记录
  ↓
Storage::disk($disk)->download($path, $o_name) → 返回下载响应
```

#### 图片URL获取
```
ImgService.getPicUrl4Id($imageId)
  ↓
FileImg::find($imageId) → 查找图片记录
  ↓
if ($fileImg->private == 1) {
    // 私有图片:需要权限验证
    return Storage::disk('local')->url($path)
} else {
    // 公开图片:直接访问
    return Storage::disk($storage_disk)->url($path)
}
```

## 4. 文件业务关联机制(重点)

### 4.1 关联设计

#### 字段说明
- **re_type**: 关联类型,标识业务用途
  - 命名规范: `模块名_实体名_用途`
  - 示例: `novel_chapter_cover`(小说章节封面)
- **re_id**: 关联业务ID
  - 对应业务实体的主键ID
  - 示例: 章节 ID

#### 状态联动
```
业务创建 → 上传文件(status='normal') → 创建业务记录 → markFileAsUsed(status='linked')
业务删除 → 删除业务记录 → 文件状态变为'dangling'(孤儿文件)
```

### 4.2 业务集成模式

#### 模式1: 上传时直接关联(推荐)
```php
// 适用于: 上传时已知业务ID
$imgService = new ImgService();
$image = $imgService->uploadImg($file, $userId, false, 'novel_chapter_cover', $chapterId);

// 文件创建时即设置 re_type 和 re_id
// 状态仍为 'normal',需后续标记为 'linked'
```

#### 模式2: 上传后关联(两步法)
```php
// 步骤1: 上传文件(不关联)
$imgService = new ImgService();
$image = $imgService->uploadImg($file, $userId, false);
// re_type='', re_id=0

// 步骤2: 业务创建后关联并标记
$chapter = Chapter::create([...]);
$image->re_type = 'novel_chapter_cover';
$image->re_id = $chapter->id;
$image->save();

FileService::markImageAsUsed($image->id);
// status='linked', used_at=now()
```

**推荐**: 模式1更简洁,适用于已知业务ID的场景;模式2更灵活,适用于业务ID未知的场景。

### 4.3 业务关联示例

#### 示例1: 小说章节封面
```php
// NovelAi模块 - 创建章节封面
$chapter = Chapter::create([...]);

$imgService = new \Modules\AFile\Services\ImgService();
$coverImage = $imgService->uploadImg(
    $request->file('cover'),
    $userId,
    false,
    'novel_chapter_cover',
    $chapter->id
);

// 标记图片为已使用
$fileService = new \Modules\AFile\Services\FileService();
$fileService->markImageAsUsed($coverImage->id);
```

#### 示例2: 用户头像
```php
// AUser模块 - 更新用户头像
$imgService = new \Modules\AFile\Services\ImgService();
$avatar = $imgService->uploadImg(
    $request->file('avatar'),
    $userId,
    false,
    'user_avatar',
    $userId
);

$fileService->markImageAsUsed($avatar->id);
```

#### 示例3: 商品主图(批量)
```php
// Product模块 - 创建商品主图
$imgService = new \Modules\AFile\Services\ImgService();
$mainImage = $imgService->uploadImg(
    $request->file('main_image'),
    $userId,
    false,
    'product_main_image',
    $productId

$fileService->markImageAsUsed($mainImage->id);
```

## 5. 存储配置管理

### 5.1 多环境配置

**核心表**: `file_storage_configs`

| 字段 | 说明 |
|------|------|
| name | 磁盘名称(唯一标识) |
| driver | 驱动类型(local/s3/oss/cos等) |
| config | JSON配置值 |
| is_default | 是否默认存储 |
| is_temp | 是否临时存储 |
| env | 环境标识(local/production等) |
| status | 启用状态 |

**特点**:
1. 支持多环境(通过 `env` 字段区分)
2. 支持多存储驱动
3. 配置历史记录(变更追踪)
4. 缓存管理(提高性能)

### 5.2 配置动态注册

```php
StorageConfigService::registerStorageConfigs()
  ↓
getAllDisks() → 获取当前环境所有配置
  ↓
foreach ($disks as $disk) {
    config(["filesystems.disks.{$disk->name}" => $config])
}
  ↓
getDefaultDisk() → 设置默认磁盘
config(['filesystems.default' => $defaultDisk->name])
```

**关键点**: 配置从数据库加载,动态注册到Laravel文件系统,启动时自动执行。

### 5.3 配置缓存管理

```php
// 缓存Key格式
file_storage_config:default:{env}
file_storage_config:temp:{env}
file_storage_config:name:{name}:{env}
file_storage_config:all:{env}

// 缓存时间
CACHE_TTL = 3600 // 1小时

// 缓存清除
StorageConfigService::clearCache()
```

**优势**: 减少数据库查询,提高配置访问性能。

```php
$temporaryService->delete($path);
```

## 8. 事件驱动架构

### 8.1 事件触发时机

| Event | 触发位置 | 时机 |
|-------|---------|------|
| FileUploadedEvent | FileLogic::uploadFile() | 文件上传后立即触发 |

4. **统计分析**: 统计文件使用情况

## 9. 业务集成最佳实践

### 9.1 文件生命周期管理

#### 创建阶段
```php
// 1. 上传文件
$file = FileService::uploadFile($uploadedFile, $userId);

// 2. 创建业务记录
$business = Business::create([...]);

// 3. 关联文件并标记使用
$file->re_type = 'module_business_usage';
$file->re_id = $business->id;
$file->save();
FileService::markFileAsUsed($file->id);
```

#### 更新阶段
```php
// 1. 删除旧文件(如果更换)
FileService::deleteFile($oldFileId);

// 2. 上传新文件
$newFile = FileService::uploadFile($uploadedFile, $userId);

// 3. 更新业务关联
$newFile->re_type = 'module_business_usage';
$newFile->re_id = $business->id;
$newFile->save();
FileService::markFileAsUsed($newFile->id);
```

#### 删除阶段
```php
// 方式1: 删除业务记录并取消文件关联(保留文件,标记为悬空)
$business = Business::find($businessId);
$files = $business->files;
$business->delete();

// 批量取消文件关联,标记为悬空状态
$fileIds = $files->pluck('id')->toArray();
FileService::batchUnlinkFiles($fileIds, true);

// 方式2: 删除业务记录并删除关联文件(彻底清理)
$business = Business::find($businessId);
$files = $business->files;
$business->delete();

// 批量取消关联并删除文件
$fileIds = $files->pluck('id')->toArray();
FileService::batchUnlinkAndDeleteFiles($fileIds);
```

### 9.2 性能优化建议

1. **批量标记**: 使用 `batchMarkAsUsed()` 避免N+1查询
2. **预加载**: 使用 `with('images')` 预加载关联图片
3. **缓存**: 缓存频繁访问的文件URL
4. **延迟加载**: 使用延迟加载关联,避免不必要的查询

### 9.3 权限控制建议

1. **私有文件**: 设置 `private=1`,需要权限验证才能访问
2. **公开文件**: 设置 `private=0`,可以直接通过URL访问
3. **业务权限**: 根据业务权限判断是否允许访问文件

## 11. 总结

### 核心优势
1. **单模块全栈**: 完整业务逻辑,多种入口形式
2. **动态存储配置**: 多环境、多驱动支持
3. **状态管理**: 文件生命周期完整追踪
4. **事件驱动**: 模块间解耦通信
5. **业务关联**: 灵活的关联机制(re_type/re_id)

### 关键机制
- **文件状态**: normal → linked → dangling
- **关联标识**: re_type(命名规范) + re_id(业务ID)
- **动态配置**: 数据库配置 + 动态注册 + 缓存
- **事件通知**: 上传/使用/删除事件驱动

### 最佳实践
- 上传时直接关联(已知业务ID)
- 业务删除时同步删除文件
- 批量标记提高性能
- 预加载关联图片
- 私有文件权限控制
