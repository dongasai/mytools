# 数据库性能测试命令

## 命令概述

`db:performance-test` 是 Application 模块提供的数据库性能测试 Artisan 命令，用于全面评估数据库查询和写入性能，帮助开发者识别性能瓶颈和优化机会。

**命令路径**：`Modules/Application/Console/DbPerformanceTestCommand.php`

---

## 功能特性

### 测试类型

| 测试类型 | 说明 | 测试场景数 |
|---------|------|-----------|
| **quick** | 快速测试 | 查询3场景 + 写入3场景 |
| **query** | 仅查询测试 | 简单查询、复杂查询、聚合查询 |
| **write** | 仅写入测试 | 单条插入、批量插入、更新操作 |
| **all** | 完整测试 | 所有测试场景 |
| **deep** | 深度测试 | 更多迭代次数，详细分析 |

### 性能指标

每个测试场景提供以下性能指标：

- **平均响应时间** (avg_time_ms)
- **最小响应时间** (min_time_ms)
- **最大响应时间** (max_time_ms)
- **中位数响应时间** (median_ms)
- **标准差** (std_dev)
- **吞吐量** (operations_per_second)

### 输出格式

支持三种输出格式：

| 格式 | 说明 | 适用场景 |
|------|------|---------|
| **text** | 详细文本报告 | 终端查看完整分析 |
| **table** | 简洁表格报告 | 快速查看关键指标 |
| **log** | 保存到日志文件 | 归档和后续分析 |

---

## 命令参数

### 核心参数

```bash
php artisan db:performance-test [选项]
```

| 参数 | 类型 | 默认值 | 说明 |
|------|------|-------|------|
| `--type` | string | quick | 测试类型（quick/query/write/all/deep） |
| `--iterations` | int | 100 | 每个测试场景的迭代次数 |
| `--output` | string | text | 输出格式（text/table/log） |
| `--save-log` | boolean | false | 是否保存详细日志到文件 |

### 高级参数

| 参数 | 类型 | 默认值 | 说明 |
|------|------|-------|------|
| `--warmup` | int | 10 | 预热迭代次数（预热不计入统计） |
| `--cleanup` | boolean | true | 测试完成后清理临时数据 |

## 测试场景说明

### 查询性能测试

#### 1. 简单查询
测试基础的单表查询性能。

**测试内容**：
- 根据 ID 查询单条记录
- 根据索引字段查询
- 简单的 WHERE 条件查询

**性能基准**：
- 优秀：< 1ms
- 良好：1-5ms
- 需优化：> 5ms

#### 2. 复杂查询
测试多表关联查询性能。

**测试内容**：
- JOIN 关联查询
- 多条件组合查询
- 子查询性能

**性能基准**：
- 优秀：< 10ms
- 良好：10-20ms
- 需优化：> 20ms

#### 3. 聚合查询
测试统计类查询性能。

**测试内容**：
- COUNT/SUM/AVG 等聚合函数
- GROUP BY 分组统计
- 时间范围查询统计

**性能基准**：
- 优秀：< 5ms
- 良好：5-15ms
- 需优化：> 15ms

### 写入性能测试

#### 1. 单条插入
测试单条记录插入速度。

**测试内容**：
- INSERT 单条记录
- 自动填充测试数据
- 立即提交

**性能基准**：
- 优秀：< 1ms
- 良好：1-3ms
- 需优化：> 3ms

#### 2. 批量插入
测试批量插入性能（100条记录）。

**测试内容**：
- 批量 INSERT 语句
- 事务批量插入
- 性能对比分析

**性能基准**：
- 优秀：< 15ms
- 良好：15-30ms
- 需优化：> 30ms

#### 3. 更新操作
测试记录更新性能。

**测试内容**：
- UPDATE 单条记录
- UPDATE 多条记录
- UPDATE OR INSERT (upsert)

**性能基准**：
- 优秀：< 1ms
- 良好：1-3ms
- 需优化：> 3ms

## 技术实现

### 核心服务类

**PerformanceTestService** (`Services/PerformanceTestService.php`)
- 协调各测试类型执行
- 管理测试流程（预热、测试、清理）
- 收集性能指标

**PerformanceReportService** (`Services/PerformanceReportService.php`)
- 生成测试报告
- 格式化输出（text/table/log）
- 性能分析和评级

### 测试实现类

**QueryPerformanceTest** (`Tests/Performance/QueryPerformanceTest.php`)
- 实现查询性能测试场景
- 使用 Laravel Benchmark 类测量性能
- 自动创建临时测试数据

**WritePerformanceTest** (`Tests/Performance/WritePerformanceTest.php`)
- 实现写入性能测试场景
- 测试各种写入操作类型
- 自动清理临时测试表

### 数据传输对象

**PerformanceTestResult** (`Dtos/PerformanceTestResult.php`)
- 封装单个测试场景的完整结果
- 包含测试配置、性能指标、评级

**PerformanceMetric** (`Dtos/PerformanceMetric.php`)
- 封装性能统计数据
- 提供平均值、最小值、最大值、中位数等统计方法

## 测试数据管理

### 测试表说明

性能测试使用两种类型的表：

**1. 查询性能测试**
- 使用实际业务表：`application_configs`
- 不创建临时表，不写入数据
- 仅执行查询操作，不影响业务数据

**2. 写入性能测试**
- 使用固定名称的临时测试表：`perf_test_table`
- 测试开始时创建，测试结束时自动删除
- 包含字段：`id`, `test_key`, `test_value`, `created_at`, `updated_at`

### 数据清理

**写入测试自动清理**：
- 测试完成后自动删除临时表 `perf_test_table`
- 清空所有测试数据
- 确保不影响业务数据

**查询测试无影响**：
- 仅查询现有业务表
- 不写入任何数据
- 对业务数据完全无影响

**清理选项**：
- 默认自动清理（`--cleanup=true`）
- 可禁用清理（`--cleanup=false`）用于问题排查（仅写入测试）

## 性能优化建议

### 识别性能瓶颈

命令会根据测试结果自动识别性能问题：

1. **慢查询识别**：平均时间超过基准阈值
2. **索引建议**：复杂查询性能差时提示添加索引
3. **N+1 问题**：关联查询性能差时提示使用预加载

### 常见优化建议

#### 查询优化

1. **添加索引**：
   ```sql
   ALTER TABLE features ADD INDEX idx_key (key);
   ```

2. **使用预加载**：
   ```php
   // 避免 N+1 问题
   Feature::with(['userSettings', 'whitelist'])->get();
   ```

3. **查询缓存**：
   ```php
   // 使用缓存减少数据库查询
   Feature::remember(3600)->where('key', $key)->first();
   ```

#### 写入优化

1. **批量插入**：
   ```php
   // 使用批量插入代替循环插入
   DB::table('job_runs')->insert($data);
   ```

2. **事务优化**：
   ```php
   // 大批量写入使用事务
   DB::transaction(function () {
       foreach ($data as $item) {
           JobRun::create($item);
       }
   });
   ```

## 适用场景

### 开发阶段

- 新功能开发完成后验证数据库性能
- 模型设计调整后评估影响
- 索引添加前后对比测试

### 性能调优

- 识别慢查询和性能瓶颈
- 评估优化措施效果
- 对比不同实现方案性能

### 生产环境巡检

- 定期执行性能测试监控数据库健康度
- 性能退化预警
- 容量规划参考

**重要提示**：
- ⚠️ 生产环境建议在低峰期执行
- ⚠️ 建议使用 `--iterations=50` 减少测试负载
- ⚠️ **查询测试**：仅查询现有数据，完全无影响
- ⚠️ **写入测试**：使用临时表，测试后自动删除，不影响业务数据

## 错误处理

### 常见错误

#### 1. 数据库连接失败

```
错误: Could not connect to database
```

**解决方案**：
- 检查 `.env` 数据库配置
- 确认数据库服务运行中
- 验证数据库连接权限

#### 2. 权限不足

```
错误: Insufficient permissions to create test tables
```

**解决方案**：
- 确认数据库用户有 CREATE TABLE 权限
- 检查表前缀配置是否正确

#### 3. 测试表已存在

```
警告: perf_test_table already exists
```

**解决方案**：
- 命令会自动删除旧的临时表
- 如遇问题可手动删除：`DROP TABLE IF EXISTS perf_test_table`
