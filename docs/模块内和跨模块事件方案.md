# 模块内事件和跨模块事件处理方案

## 核心架构

### 双Event设计

```
模块内Event(完整参数) → 同步Listener(模块内业务) + 异步统一转发器 → 跨模块Event(精简参数) → 异步Listener(跨模块业务)
```

**核心原则**：
- **模块内Event**：完整参数，无前缀，**同步处理**模块内业务
- **跨模块Event**：精简参数，`Module`前缀，**异步处理**跨模块业务
- **统一转发器**：一个模块一个，eventMap配置，队列`event`，异步转发
- **跨模块监听优先异步**：避免阻塞主业务流程，提高系统响应速度

---

## 跨模块监听优先异步原则 ⭐

### 为什么跨模块监听必须异步？

**核心原因**：
1. **避免阻塞主业务**：Account注册完成后，不应等待User创建、Referral推广处理等跨模块业务
2. **提高响应速度**：用户感知的响应时间只包含核心业务（Account创建），跨模块业务异步处理不影响用户体验
3. **解耦失败影响**：跨模块业务失败（如推广关系建立失败）不应导致主业务失败（Account注册成功）
4. **提高系统弹性**：跨模块业务失败可重试（tries=3），不影响主业务成功状态

### 同步 vs 异步选择标准

| 监听器类型 | 执行方式 | 队列配置 | 适用场景 |
|-----------|---------|---------|---------|
| **模块内Listener** | 同步 | 不实现 ShouldQueue | 日志记录、统计更新、缓存清理 |
| **统一转发器** | 异步 | queue=event, tries=3 | 转发模块内Event到跨模块Event |
| **跨模块Listener** | 异步 | queue=event, tries=3 | 创建关联数据、处理推广、发送通知 |

**判断原则**：
- ✅ 模块内业务 → 同步（快速、简单、必须成功）
- ✅ 跨模块业务 → 异步（复杂、耗时、可独立失败）
- ❌ 跨模块业务同步处理 → 阻塞主业务，降低响应速度

## 异步监听标准配置

### 统一转发器配置（ModuleDispatcher）

```php
// Modules/ABase/Listeners/ModuleDispatcher.php
abstract class ModuleDispatcher implements ShouldQueue
{
    use Queueable;

    // 标准配置：队列event，重试3次，超时30秒
    public int $tries = 3;         // 失败重试3次
    public int $timeout = 30;      // 单次执行超时30秒
    public ?string $queue = 'event'; // 专用事件队列

    protected array $eventMap = [];

    public function handle(object $event): void
    {
        // 提取参数，转发跨模块Event
        $config['target']::dispatch(...array_values($payload));
    }
}
```

**配置说明**：
- `queue=event`：专用队列，避免与业务队列混淆
- `tries=3`：失败自动重试，提高可靠性
- `timeout=30`：超时保护，避免长时间阻塞队列

### 跨模块Listener配置示例

```php
// Modules/Referral/Listeners/HandleAccountRegisteredListener.php
class HandleAccountRegisteredListener implements ShouldQueue
{
    use Queueable;

    // 标准异步配置
    public string $queue = 'event';   // 专用事件队列
    public int $tries = 3;            // 重试3次
    public int $maxExceptions = 3;    // 最大异常数

    public function handle(ModuleAccountRegisteredEvent $event): void
    {
        // 处理推广关系（跨模块业务）
        $referralRelation = ReferralService::createReferralRelation(...);

        // 发放推广奖励（调用Point模块）
        ReferralService::processReferralRewards(...);
    }

    // 失败处理
    public function failed(ModuleAccountRegisteredEvent $event, \Exception $exception): void
    {
        Logger::error('推广处理最终失败', [...]);
    }
}
```

## 统一转发器架构

### 基类（ModuleDispatcher）

```php
// Modules/Base/Listeners/ModuleDispatcher.php
abstract class ModuleDispatcher implements ShouldQueue
{
    use Queueable;

    public int $tries = 3;
    public int $timeout = 30;
    public string $queue = 'event';

    protected array $eventMap = [];

    public function handle(object $event): void
    {
        $eventClass = get_class($event);

        if (!isset($this->eventMap[$eventClass])) {
            return;
        }

        $config = $this->eventMap[$eventClass];

        // 条件验证(可选)
        if (isset($config['condition']) && method_exists($event, $config['condition'])) {
            if (!$event->{$config['condition']}()) {
                return;
            }
        }

        // 提取参数
        $payload = [];
        foreach ($config['fields'] as $field) {
            if (property_exists($event, $field)) {
                $payload[$field] = $event->{$field};
            }
        }

        // 转发跨模块Event
        $config['target']::dispatch(...$payload);
    }
}
```

### 转发器实现（一个模块一个）

```php
// Modules/Account/Listeners/DispatchModuleAccount.php
class DispatchModuleAccount extends ModuleDispatcher
{
    protected array $eventMap = [
        AccountCreatedEvent::class => [
            'target' => ModuleAccountCreatedEvent::class,
            'fields' => ['account'],
        ],

        // 新增Event只需配置eventMap
        // AccountUpdatedEvent::class => [
        //     'target' => ModuleAccountUpdatedEvent::class,
        //     'fields' => ['account', 'changes'],
        // ],
    ];
}
```

**优势**：
- 一个转发器处理所有模块Event（减少90%代码）
- eventMap集中配置，易于维护
- 支持条件验证、字段过滤

## 同步/异步处理规范（核心原则）⭐

### 模块内Listener（同步执行）

```php
// Modules/Account/Listeners/LogAccountCreatedListener.php
class LogAccountCreatedListener  // 不实现 ShouldQueue
{
    public function handle(AccountCreatedEvent $event): void
    {
        Log::info('账户创建', $event->getLogData());
    }
}
```

**原则**：
- ❌ **不实现 `ShouldQueue`**
- ✅ **同步执行**：立即处理，不推送到队列
- ✅ **快速完成**：毫秒级处理（日志、统计、缓存）
- ✅ **必须成功**：失败会影响主业务

**适用场景**：
- 日志记录（毫秒级）
- 统计数据更新（简单计算）
- 缓存清理（快速操作）

---

### 统一转发器（异步执行）

```php
// Modules/ABase/Listeners/ModuleDispatcher.php
abstract class ModuleDispatcher implements ShouldQueue
{
    use Queueable;

    public string $queue = 'event';  // 专用队列
    public int $tries = 3;           // 重试机制
    public int $timeout = 30;        // 超时保护

    public function handle(object $event): void
    {
        // 转发跨模块Event
        event(new $config['target'](...$payload));
    }
}
```

**原则**：
- ✅ **实现 `ShouldQueue`**
- ✅ **队列 `event`**：专用队列，与业务队列隔离
- ✅ **重试机制**：`tries=3`，失败自动重试
- ✅ **超时保护**：`timeout=30`，避免长时间阻塞队列

**职责**：
- 转发模块内Event到跨模块Event
- 参数过滤和精简
- 条件验证（可选）

---

### 跨模块Listener（异步执行）⭐

```php
// Modules/User/Listeners/CreateDefaultUser.php
class CreateDefaultUser implements ShouldQueue
{
    use Queueable;

    public string $queue = 'event';  // 专用队列
    public int $tries = 3;           // 重试机制

    public function handle(ModuleAccountCreatedEvent $event): void
    {
        // 创建默认用户（跨模块业务）
        User::create(['account_id' => $event->account->id]);
    }

    public function failed(ModuleAccountCreatedEvent $event, \Exception $e): void
    {
        Log::error('创建User失败', ['account_id' => $event->account->id]);
    }
}
```

**原则（跨模块监听核心原则）**：
- ✅ **必须实现 `ShouldQueue`**：异步执行
- ✅ **队列 `event`**：专用队列，统一管理
- ✅ **重试机制**：`tries=3`，提高可靠性
- ✅ **失败处理**：实现 `failed()` 方法，记录失败日志
- ❌ **禁止同步监听**：避免阻塞主业务流程

**为什么必须异步？**：
1. **避免阻塞主业务**：Account注册不应等待User创建完成
2. **提高响应速度**：用户感知的响应时间不含跨模块业务
3. **失败隔离**：跨模块业务失败不影响主业务成功
4. **弹性提高**：队列重试机制保证最终完成

**适用场景**：
- 创建关联数据（User、Profile、Settings）
- 处理推广关系（Referral验证、奖励发放）
- 发送通知（邮件、推送、短信）
- 更新统计（跨模块数据汇总）
- 调用第三方服务（耗时操作）

## EventServiceProvider注册规范

### 模块内Event注册（发起模块）

```php
// Modules/Account/Providers/EventServiceProvider.php
protected $listen = [
    // 模块内Event（完整参数）
    AccountCreatedEvent::class => [
        LogAccountCreatedListener::class,  // 同步：模块内业务（日志）
        DispatchModuleAccount::class,      // 异步：统一转发器（queue:event）
    ],

    AccountRegistered::class => [
        DispatchModuleAccount::class,      // 异步：转发跨模块Event
    ],

    // 跨模块Event（精简参数） - 不在本模块注册监听器
    ModuleAccountCreatedEvent::class => [
        // 其他模块在自己的 EventServiceProvider 中注册监听器
        // 保持模块独立性，不在这里注册
    ],
];
```

**注册原则**：
1. **模块内Event**：注册同步Listener + 异步转发器
2. **跨模块Event**：不注册监听器（保持模块独立）
3. **执行顺序**：同步Listener优先，异步转发器其次（队列顺序）

---

### 跨模块Event注册（监听模块）⭐

```php
// Modules/User/Providers/EventServiceProvider.php
protected $listen = [
    // 监听 Account 模块的跨模块Event
    ModuleAccountCreatedEvent::class => [
        CreateDefaultUser::class,  // 异步：创建User（queue:event）
    ],
];

// Modules/Referral/Providers/EventServiceProvider.php
protected $listen = [
    // 监听 Account 模块的注册事件
    AccountRegistered::class => [
        HandleAccountRegisteredListener::class,  // 异步：处理推广（queue:event）
    ],
];
```

**跨模块监听核心原则**：
1. ✅ **监听模块注册**：在自己模块的 EventServiceProvider 注册
2. ✅ **必须异步监听**：Listener 实现 ShouldQueue + queue=event
3. ✅ **重试机制**：tries=3，失败自动重试
4. ✅ **失败处理**：实现 failed() 方法
5. ❌ **禁止同步监听**：避免阻塞发起模块的主业务

**为什么在其他模块注册？**：
- 模块解耦：Account模块不知道User模块监听它的Event
- 独立部署：User模块可独立启用/禁用，不影响Account模块
- 灵活扩展：新增模块监听ModuleAccountCreatedEvent，无需修改Account模块

---

### 执行顺序和队列流程

**同步Listener执行顺序**：
```
AccountCreatedEvent触发 → 同步执行
  ├─ LogAccountCreatedListener（同步，立即执行）
  │  └─ Log::info('账户创建') - 毫秒级完成
  │
  └─ DispatchModuleAccount（异步，推送到队列）
     └─ dispatch ModuleAccountCreatedEvent - 推送完成，继续

返回 Account对象给用户 ← 同步部分完成
```

**异步Listener队列执行**：
```
Queue Worker处理队列（event队列）
  ├─ DispatchModuleAccount（转发器）
  │  └─ event(new ModuleAccountCreatedEvent($account))
  │
  └─ CreateDefaultUser（User模块监听）
     └─ User::create(['account_id' => $account->id])
     └─ 失败重试tries=3

  └─ HandleAccountRegisteredListener（Referral模块监听）
     └─ ReferralService::createReferralRelation()
     └─ ReferralService::processReferralRewards()
     └─ 失败重试tries=3
```

**时间对比**：
- 同步部分（用户感知）：Account创建 + 日志 ≈ 50ms
- 异步部分（用户无感知）：User创建 + Referral处理 ≈ 500ms（队列执行）

**用户体验**：
- ✅ 用户响应时间：50ms（不含跨模块业务）
- ✅ 跨模块业务失败不影响：Account注册成功
- ✅ 系统弹性：队列重试保证最终完成

## 新增Event流程

1. **定义模块内Event**（完整参数）
2. **定义跨模块Event**（精简参数）
3. **配置eventMap**（无需创建新转发器）
4. **注册EventServiceProvider**

**示例**：新增AccountUpdatedEvent

```php
// 1. 模块内Event
class AccountUpdatedEvent {
    public Account $account;
    public array $changes;
}

// 2. 跨模块Event
class ModuleAccountUpdatedEvent {
    public Account $account;
}

// 3. 配置eventMap
protected array $eventMap = [
    AccountCreatedEvent::class => [...],
    AccountUpdatedEvent::class => [
        'target' => ModuleAccountUpdatedEvent::class,
        'fields' => ['account'],
    ],
];

// 4. 注册EventServiceProvider
AccountUpdatedEvent::class => [
    LogAccountUpdatedListener::class,
    DispatchModuleAccount::class, // 同一个转发器
],
```

## 实际案例分析

### 案例1: Account注册 → User创建（标准跨模块异步监听）

**完整执行流程**：

```
1. Account::createAccount() 触发 AccountCreatedEvent（模块内）
   ↓ 同步执行（主业务流程）

2. LogAccountCreatedListener（同步）
   - 记录账户创建日志
   - 不阻塞，立即完成
   ↓ 同步完成

3. DispatchModuleAccount（异步，queue=event）
   - 提取参数：account
   - 转发 ModuleAccountCreatedEvent
   ↓ 异步推送到队列

4. 【主业务完成】返回 Account 对象给用户
   - 用户感知：注册成功
   - 响应时间：只包含步骤1-3的同步部分
   ↓

5. Queue Worker 处理 ModuleAccountCreatedEvent
   ↓ 异步执行（不影响用户）

6. CreateDefaultUser（异步，queue=event）
   - 创建默认 User 记录
   - 失败重试 tries=3
   - 失败不影响 Account 注册成功状态
```

**关键代码**：

```php
// Account模块：Service触发事件
public static function createAccount(...): Account
{
    $account = Account::create([...]);

    // 触发模块内Event（同步）
    event(new AccountCreatedEvent($account, $data));

    return $account; // 立即返回，不等待跨模块业务
}

// Account模块：EventServiceProvider注册
protected $listen = [
    AccountCreatedEvent::class => [
        LogAccountCreatedListener::class,  // 同步：日志记录
        DispatchModuleAccount::class,      // 异步：转发跨模块Event
    ],

    ModuleAccountCreatedEvent::class => [
        // 其他模块监听（不在本模块注册）
    ],
];

// User模块：跨模块监听
protected $listen = [
    ModuleAccountCreatedEvent::class => [
        CreateDefaultUser::class, // 异步：创建User
    ],
];
```

**用户体验**：
- ✅ 注册响应快：只等待 Account 创建 + 日志记录（毫秒级）
- ✅ User创建失败不影响：Account 注册成功，User 可后续补充创建
- ✅ 系统弹性高：队列重试机制保证跨模块业务最终完成

### 案例2: Account注册 → Referral推广处理（异步监听）

**完整执行流程**：

```
1. Account::createAccount($isRegistration=true)
   ↓

2. AccountCreatedEvent → LogAccountCreatedListener（同步日志）
   DispatchModuleAccount → ModuleAccountCreatedEvent（异步转发）
   ↓

3. AccountRegistered → DispatchModuleAccount（异步转发）
   ↓ 提取 referralCode

4. ModuleAccountRegisteredEvent
   ↓ 异步队列

5. HandleAccountRegisteredListener（异步，queue=event）
   - 验证推广码
   - 建立推广关系
   - 发放推广奖励（调用Point模块）
   - 失败重试 tries=3
```

**关键代码**：

```php
// Account模块：Service触发注册事件
public static function createAccount(..., bool $isRegistration = false): Account
{
    $account = Account::create([...]);

    event(new AccountCreatedEvent($account, $data));

    // 注册场景触发额外事件
    if ($isRegistration) {
        event(new AccountRegistered($account, $data)); // 包含referral_code
    }

    return $account;
}

// Referral模块：跨模块监听
protected $listen = [
    AccountRegistered::class => [
        HandleAccountRegisteredListener::class, // 异步处理推广
    ],
];

// Referral Listener：异步配置
class HandleAccountRegisteredListener implements ShouldQueue
{
    public string $queue = 'event';
    public int $tries = 3;

    public function handle(AccountRegistered $event): void
    {
        // 验证推广码
        if (!ReferralService::validateReferralCode($event->data['referral_code'])) {
            return; // 无推广码，跳过
        }

        // 建立推广关系（跨模块业务）
        $referralRelation = ReferralService::createReferralRelation(...);

        // 发放奖励（调用Point模块）
        ReferralService::processReferralRewards(...);
    }
}
```

**异步监听优势**：
- ✅ 推广处理失败不影响注册成功
- ✅ 推广业务耗时（验证、奖励）不阻塞用户响应
- ✅ 重试机制保证推广关系最终建立

### 案例3: Novel发布 → 多模块异步监听

**完整执行流程**：

```
1. NovelService::publishNovel()
   ↓

2. NovelPublishedEvent → LogNovelPublishedListener（同步日志）
   DispatchModuleNovel → ModuleNovelPublishedEvent（异步转发）
   ↓ 异步队列

3. ModuleNovelPublishedEvent
   ↓ 异步触发多个Listener

4. 多个模块异步监听：
   - NotificationListener（发送通知）
   - StatisticsListener（更新统计）
   - SearchListener（更新搜索索引）

```

**关键代码**：

```php
// NovelBase模块：统一转发器配置
class DispatchModuleNovel extends ModuleDispatcher
{
    protected array $eventMap = [
        NovelPublishedEvent::class => [
            'target' => ModuleNovelPublishedEvent::class,
            'fields' => ['novel'],

// NovelBase模块：EventServiceProvider注册
protected $listen = [
    NovelPublishedEvent::class => [

    ],
];
```

**多模块异步监听优势**：
- ✅ 小说发布响应快：只等待 Novel 状态更新 + 日志记录
- ✅ 多个跨模块业务并行异步处理（通知、统计、搜索、奖励）
- ✅ 任一模块失败不影响发布成功和其他模块业务

**文件结构**：
```
Modules/Account/
├── Events/
│   ├── AccountCreatedEvent.php         (模块内)
│   └── ModuleAccountCreatedEvent.php   (跨模块)
├── Listeners/
│   ├── LogAccountCreatedListener.php   (同步)
│   └── DispatchModuleAccount.php       (异步统一转发器)
└── Providers/
    └── EventServiceProvider.php

Modules/User/Listeners/
└── CreateDefaultUser.php               (异步监听跨模块Event)
```

**执行流程**：
```
Account创建 → AccountCreatedEvent(同步)
  → LogAccountCreatedListener(同步日志)
  → DispatchModuleAccount(异步转发,queue:event)
    → ModuleAccountCreatedEvent
      → CreateDefaultUser(异步创建User,queue:event)
```

---

## 核心价值

1. **参数明确**：Event类定义明确参数，IDE提示，类型安全
2. **代码简洁**：统一转发器，减少90%代码量
3. **易于调试**：标准Laravel Event机制，所有代码可见
4. **易于扩展**：新增Event只需配置eventMap
5. **配置集中**：一个模块一个转发器，eventMap统一管理
6. **职责分离**：模块内完整参数，跨模块精简参数，转发层参数过滤
7. **响应速度快**：异步跨模块监听，主业务毫秒级响应
8. **系统弹性高**：队列重试机制，失败隔离，最终保证完成

---

## 最佳实践（核心原则总结）⭐

### ✅ 正确做法

**模块内监听（同步）**：
- 模块内Listener **不实现** `ShouldQueue`（同步执行）
- 处理简单业务：日志、统计、缓存（毫秒级）
- 失败会影响主业务：必须成功

**跨模块监听（异步）**：
- 跨模块Listener **必须实现** `ShouldQueue` + queue=`event`（异步执行）
- 处理复杂业务：创建关联数据、处理推广、发送通知（秒级）
- 失败不影响主业务：可独立失败，队列重试

**统一转发器**：
- 继承 `ModuleDispatcher` 基类（异步配置已标准化）
- 使用 eventMap 配置多个Event（无需创建新转发器）
- 队列 `event`，tries=3，timeout=30（标准配置）

**参数设计**：
- 模块内Event：完整参数（满足模块内业务需求）
- 跨模块Event：精简参数（只传递核心信息：account、novel等）
- 转发器：参数过滤（fields配置）+ 条件验证（condition配置）

**模块注册**：
- 发起模块：注册模块内Event + Listener（同步）+ 转发器（异步）
- 监听模块：注册跨模块Event + Listener（异步）
- 跨模块Event：不在发起模块注册监听器（保持模块独立）

---

### ❌ 避免做法（严重错误）

**跨模块同步监听（阻塞主业务）**：
```php
// ❌ 错误：跨模块Listener同步执行
class CreateDefaultUser  // 不实现 ShouldQueue
{
    public function handle(ModuleAccountCreatedEvent $event): void
    {
        User::create(...);  // 同步阻塞Account注册响应
    }
}
```
**危害**：
- Account注册响应时间 = Account创建 + User创建 ≈ 200ms（慢）
- User创建失败 → Account注册失败（不合理）

**正确做法**：
```php
// ✅ 正确：跨模块Listener异步执行
class CreateDefaultUser implements ShouldQueue
{
    public string $queue = 'event';
    public int $tries = 3;

    public function handle(ModuleAccountCreatedEvent $event): void
    {
        User::create(...);  // 异步执行，不阻塞Account注册
    }
}
```
**优势**：
- Account注册响应时间 ≈ 50ms（快）
- User创建失败 → Account注册依然成功（合理）
- 队列重试 → User最终创建成功（弹性）

---

**每个Event创建单独转发器（代码冗余）**：
```php
// ❌ 错误：每个Event一个转发器（90%冗余代码）
class DispatchModuleAccountCreated { ... }
class DispatchModuleAccountUpdated { ... }
class DispatchModuleAccountDeleted { ... }
```
**正确做法**：
```php
// ✅ 正确：一个模块一个统一转发器
class DispatchModuleAccount extends ModuleDispatcher
{
    protected array $eventMap = [
        AccountCreatedEvent::class => ['target' => ModuleAccountCreatedEvent::class, ...],
        AccountUpdatedEvent::class => ['target' => ModuleAccountUpdatedEvent::class, ...],
        AccountDeletedEvent::class => ['target' => ModuleAccountDeletedEvent::class, ...],
    ];
}
```

---

**跨模块Event传递完整参数（性能浪费）**：
```php
// ❌ 错误：跨模块Event传递完整参数
class ModuleAccountCreatedEvent {
    public Account $account;
    public array $data;  // 不需要，其他模块不需要完整data
}
```
**正确做法**：
```php
// ✅ 正确：跨模块Event精简参数
class ModuleAccountCreatedEvent {
    public Account $account;  // 只传递核心信息
}
```

---

**模块内Listener异步处理（降低性能）**：
```php
// ❌ 错误：模块内日志Listener异步执行
class LogAccountCreatedListener implements ShouldQueue
{
    public function handle(AccountCreatedEvent $event): void
    {
        Log::info(...);  // 简单日志，异步执行浪费队列资源
    }
}
```
**正确做法**：
```php
// ✅ 正确：模块内日志Listener同步执行
class LogAccountCreatedListener  // 不实现 ShouldQueue
{
    public function handle(AccountCreatedEvent $event): void
    {
        Log::info(...);  // 同步毫秒级完成，不浪费队列
    }
}
```
