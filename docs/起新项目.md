# 起新项目流程

本文档描述如何基于现有项目（老项目）创建新项目的完整流程。

## 一、准备工作

### 1.1 确认新项目信息

在开始之前，需要明确以下信息：

- **项目名称**：中文全称、简称、英文标识
- **项目定位**：核心业务方向、目标用户、核心功能
- **技术选型**：是否沿用现有技术栈、是否需要新的依赖

**示例**：
- 中文名：个人工具
- 英文名：mytool
- 定位：个人工具集合

## 二、Git 处理

### 2.1 检查 Git 状态

在处理 Git 之前，先检查当前状态：

```bash
# 查看当前状态
git status

# 查看远程仓库
git remote -v

# 查看提交历史
git log --oneline -10
```

### 2.2 确定处理方案

根据检查结果选择方案：

| 场景 | 判断标准 | 处理方案 |
|------|----------|----------|
| **Git 已是新项目** | 远程仓库地址是新项目 | 无需处理，继续下一步 |
| **Git 是老项目** | 远程仓库地址是老项目 | 修改远程仓库地址 |
| **需要全新历史** | 希望完全独立的新仓库 | 重新初始化 Git |

### 2.3 执行处理

**方案一：无需处理**
```bash
# 远程仓库已是新项目，跳过此步骤
```

**方案二：修改远程仓库**
```bash
# 修改远程仓库地址
git remote set-url origin <new-repository-url>

# 验证修改
git remote -v
```

**方案三：重新初始化**
```bash
# 删除旧 Git 历史
rm -rf .git

# 初始化新仓库
git init
git add .
git commit -m "初始化新项目"

# 添加远程仓库
git remote add origin <new-repository-url>
```

## 三、清理 AiWork

### 3.1 确定处理方案

根据实际情况选择合适的处理方案：

| 方案 | 适用场景 | 数据保留 | 操作复杂度 |
|------|----------|----------|-----------|
| **方案一**：归档旧日志 | 保留历史记录，便于回溯 | ✅ 保留 | 简单 |
| **方案二**：删除旧日志 | 全新项目，不需要历史记录 | ❌ 删除 | 简单 |
| **方案三**：不处理 | 继续使用现有工作日志 | ✅ 保留 | 无 |

### 3.2 执行处理

**方案一：归档旧日志**
```bash
# 创建归档目录
mkdir -p AiWork/archive/$(date +%Y%m)-老项目名称

# 移动旧工作日志
mv AiWork/2025* AiWork/archive/$(date +%Y%m)-老项目名称/
mv AiWork/2026* AiWork/archive/$(date +%Y%m)-老项目名称/  # 根据实际情况调整
```

**方案二：删除旧日志**
```bash
# 删除所有旧工作日志
rm -rf AiWork/2025*
rm -rf AiWork/2026*  # 根据实际情况调整
```

**方案三：不处理**
```bash
# 无需操作，继续使用现有工作日志
```

## 五、清理文件

### 5.1 清理业务模块

根据新项目定位，决定保留哪些模块：

**检查现有模块**：
```bash
# 查看模块状态
php artisan module:list

# 或直接查看模块目录
ls -la Modules/
```

**编辑 modules_statuses.json**：
```json
{
    "ABase": true,           // 核心基础，必须保留
    "ApiProto": true,        // API框架，必须保留
    "DcatAdmin": true,       // 后台框架，必须保留
    "FeatureAi": true,       // 新项目核心模块
    "FeatureExcel": true,    // 通用功能，可保留
    "Notification": true,    // 通用功能，可保留
    "OldBusinessModule": false,  // 老项目业务，禁用或删除
    "NtEnergy": false,       // 能碳业务，禁用或删除
    "NtCarbon": false        // 老业务，禁用或删除
}
```

**删除不需要的模块目录**：
```bash
# 删除老项目业务模块（示例）
rm -rf Modules/NtEnergy
rm -rf Modules/NtCarbon
rm -rf Modules/Enterprise
rm -rf Modules/OldBusiness
```

### 5.2 清理文档文件

**删除老项目业务文档**：
```bash
# 删除业务相关文档
rm -rf docs/老业务*.md
rm -rf docs/特定功能文档.md
```

**保留的技术文档**：
- 架构设计文档
- 技术选型文档
- API规范文档
- 开发规范文档

### 5.3 清理 Proto 文件

**删除老业务 Proto 文件**：
```bash
# 进入 ApiProto 模块
cd Modules/ApiProto

# 删除老业务的 proto 文件
rm -rf protos/old_business/
rm -rf Protobuf/OldBusiness/
```

**更新 ApiProto 配置**：
编辑 `Modules/ApiProto/config/api_proto.php`，移除不存在模块的映射：

```php
'enabled_modules' => [
    // 'enterprise' => 'Enterprise',     // 删除不存在的模块
    // 'nt_energy' => 'NtEnergy',        // 删除不存在的模块
    'feature_ai' => 'FeatureAi',         // 保留存在的模块
],
```

### 5.4 清理数据库迁移文件

**删除不存在模块的迁移文件**：
```bash
# 删除主应用迁移（如果有）
rm -f database/migrations/*老业务*.php

# 删除模块迁移（如果模块已删除）
rm -rf Modules/OldBusiness/Database/migrations/
```

**注意**：如果数据库已经存在老业务的数据表，需要单独处理（见第五章）。

### 6.3 验证 Dcat Admin 配置

Dcat Admin 使用环境变量控制后台名称，无需修改代码：

```bash

cat .env | grep APP_TITLE

# 应该显示

```

**配置说明**：
- 后台名称自动读取 `APP_TITLE` 环境变量
- 配置文件：`config/admin.php` 已使用 `env('APP_TITLE', '开发者')`
- 后台标题将显示为：`{APP_TITLE}后台`

**如需修改**：
```bash
# 修改 .env 文件
vi .env

# 修改此行
APP_TITLE=新项目名称
```

**方法一：修改 config/admin.php**（如果允许修改）
```bash
vi config/admin.php
```

```php
return [
    'name' => '新项目名称',
    'title' => '新项目标题',
    'logo' => '新Logo路径',
];
```

**方法二：通过 ServiceProvider 覆盖配置**（推荐）

编辑 `Modules/DcatAdmin/Providers/DcatAdminServiceProvider.php`：
```php
public function boot(): void
{
    parent::boot();

    // 覆盖后台配置
    config(['admin.name' => '新项目名称']);
    config(['admin.title' => '新项目标题']);
}
```

## 七、处理数据库

### 7.1 检查数据库状态

**必须从空数据库开始**，先检查当前数据库状态：

```bash
# 查看数据库信息
php artisan db:show

# 输出示例：
# Database: sanniu
# Tables: 0  ← 必须是 0（空数据库）
```

**如果表数量不为 0**，需要清空数据库：

```bash
# 方案一：清空数据库（推荐）
php artisan db:wipe --force

# 方案二：删除并重建数据库
mysql -u root -p
DROP DATABASE sanniu;
CREATE DATABASE sanniu CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
exit;
```

**验证数据库为空**：
```bash
php artisan db:show | grep Tables
# Tables: 0  ← 确认是 0
```

### 7.2 检查环境变量配置

验证 `.env` 中的数据库配置：

```bash
cat .env | grep DB_
```

确认以下配置正确：
```env
DB_DATABASE=sanniu
DB_USERNAME=sanniu
DB_PASSWORD=你的密码
```

### 7.3 执行数据库迁移

从空数据库开始执行迁移：

```bash
# 1. 运行基础迁移
php artisan migrate

# 2. 运行所有模块迁移
php artisan module:migrate --all

# 3. 验证迁移状态
php artisan module:migrate-status
```

## 八、重新构建 Proto API

清理模块后，需要重新构建 Proto API：

```bash
# 1. 清理旧的生成文件
rm -rf Modules/ApiProto/Protobuf/*

# 2. 重新生成 Proto
composer proto

# 这个命令会自动执行：
# - apiproto:gather-proto    （归拢 proto 文件）
# - apiproto:generate-proto  （编译生成 PHP 类）
# - apiproto:fix-namespace   （修复命名空间）
# - apiproto:generate-pathlist （生成路由映射）
# - git add -f 强制添加生成文件
```

**验证 Proto 生成**：
```bash
# 查看生成的文件
ls -la Modules/ApiProto/Protobuf/

# 查看 pathlist 映射
cat Modules/ApiProto/config/pathlist.php
```

## 十三、重新部署，更新域名

### 13.1 更新域名配置

新项目需要更新域名配置，确保域名与项目定位一致：

**需要更新的文件**：

#### .env 文件

```bash
vi .env
```

更新以下配置：
```env
APP_URL=http://新项目域名

# 前端域名（如果有）
FRONTEND_URL=http://前端域名

# 如果使用了其他服务，也需要更新相关域名
```

#### .env.example 文件

```bash
vi .env.example
```

同步更新示例配置：
```env
APP_URL=http://新项目域名
FRONTEND_URL=http://前端域名
```

### 13.2 更新 Nginx 配置

如果项目通过 Nginx 运行，需要更新 Nginx 配置：

```bash
# 查看 Nginx 配置文件
ls /www/server/panel/vhost/nginx/

# 编辑域名配置文件
vi /www/server/panel/vhost/nginx/新项目域名.conf
```

**更新内容**：
- server_name：更新为新域名
- root：确认项目路径正确
- access_log、error_log：更新日志文件名

**示例**：
```nginx
server {
    listen 80;
    server_name codennn.example.com;  # 新域名

    root /data/wwwroot/project/codennn/laravel_modules/public;
    index index.php index.html;

    access_log /www/wwwlogs/codennn.access.log;
    error_log /www/wwwlogs/codennn.error.log;

    # ... 其他配置
}
```

**重载 Nginx**：
```bash
# 测试配置
nginx -t

# 重载配置
nginx -s reload

# 或使用宝塔面板
bt reload
```

### 13.3 更新 SSL 证书（如需要）

如果使用 HTTPS，需要更新 SSL 证书：

```bash
# 使用宝塔面板申请证书
# 或手动申请 Let's Encrypt 证书

# 更新证书后，更新 Nginx 配置
vi /www/server/panel/vhost/nginx/新项目域名.conf

# 添加 SSL 配置
ssl_certificate /www/server/panel/vhost/cert/新项目域名/fullchain.pem;
ssl_certificate_key /www/server/panel/vhost/cert/新项目域名/privkey.pem;
```

### 13.4 更新 hosts 文件（本地测试）

如果是在本地测试，更新 hosts 文件：

```bash
# Linux/Mac
```


## 十五、注意事项

### 15.1 必须保留的核心模块

以下模块是系统基础，**绝对不能删除**：

| 模块 | 说明 | 删除后果 |
|------|------|----------|
| **ABase** | 基础工具模块 | 所有模块失效 |
| **ApiProto** | API框架 | Proto API无法工作 |
| **DcatAdmin** | 后台框架 | 超管后台无法访问 |

### 15.2 Git 多仓库处理

如果项目使用了 git-mrepo 管理多个子仓库：

```bash
# 查看子仓库配置
cat .gitmrepo

# 更新子仓库远程地址（如需要）
# 手动编辑 .gitmrepo 文件
```

### 15.3 环境变量安全

- **不要提交 .env 文件到 Git**
- 确认 .env 中没有老项目的敏感信息（API密钥、第三方配置等）
- 更新所有第三方服务的配置（如果独立运营）

### 15.4 第三方服务配置

如果老项目集成了第三方服务，需要：

- 申请新的应用ID/密钥
- 更新回调地址（如支付、OAuth等）
- 更新跨域配置（CORS）

### 15.5 依赖包检查

检查 composer.json 中的依赖包是否都需要：

```bash
# 查看安装的包
composer show

# 移除不需要的包
composer remove package/name
```

### 15.6 日志和临时文件

```bash
# 清理日志文件
rm -rf storage/logs/*.log

# 清理临时文件
rm -rf storage/framework/cache/*
```

## 十六、常见问题

### Q1: 模块删除后报错"Class not found"

**原因**：其他模块或代码还在引用已删除的模块类。

**解决**：
```bash
# 清理自动加载
composer dump-autoload

# 搜索引用
grep -r "Modules\\OldBusiness" Modules/
```

### Q2: Proto API 路由 404

**原因**：pathlist.php 中还存在已删除模块的路由映射。

**解决**：
```bash
# 重新生成 pathlist
composer proto

# 清理路由缓存
php artisan route:clear
```

### Q3: 数据库迁移失败

**原因**：迁移文件中引用了已删除的表或字段。

**解决**：
```bash
# 检查迁移文件
grep -r "old_table" database/migrations/
grep -r "old_table" Modules/*/Database/migrations/

# 删除或修改相关迁移文件
```

### Q4: Dcat Admin 后台样式异常

**原因**：前端资源没有发布或缓存问题。

**解决**：
```bash
# 重新发布前端资源
php artisan vendor:publish --tag=dcat-admin-assets --force

# 清理浏览器缓存，强制刷新（Ctrl+F5）
```

### Q5: 老项目的 Event/Hook 监听器还在执行

**原因**：清理模块时没有移除监听器注册。

**解决**：
```bash
# 查看 Hook 列表
php artisan hook:list

# 搜索监听器注册
grep -r "Event::listen" Modules/
grep -r "HookManager::register" Modules/

# 删除相关代码
```

   - 推荐清空数据库重新迁移
   - 确保从干净状态开始

   - 使用清晰的提交信息
   - 一次性提交所有变更
