# 项目文档管理技能

此技能用于确保项目文档的正确分类、命名和存放位置,防止违反文档管理规范。

---

## 核心原则

**文档分类五类型**:
1. **长期使用** → `docs/` (图书馆)
2. **临时追踪(进行中)** → `AiWork/` (无年月,工作台)
3. **临时追踪(已完成)** → `AiWork/{年月}/` (归档)
4. **工作日志** → `AiWork/{年月}/` (按年月分类)
5. **进度总览** → `AiWork/Work.md` (总览)

**追踪文档生命周期**:
- **进行中**: 任务未完成 → `AiWork/` (无年月)
- **已完成**: 任务完成 → 归档到 `AiWork/{年月}/`

**追踪文档唯一性原则**:
- 追踪类任务必须单文档维护
- 全过程在同一份文档记录
- 不为每个阶段创建独立文档

---

## 文档分类决策流程

### 步骤1: 判断文档性质

**判断维度**:

| 维度 | 追踪文档(进行中) | 追踪文档(已完成) | 工作日志 | 成果文档 | 进度总览 |
|------|----------------|----------------|---------|---------|---------|
| **使用周期** | 临时进行中 | 临时已完成 | 按年月归档 | 长期使用 | 持续使用 |
| **内容性质** | 过程记录 | 过程记录完成 | 日志记录 | 成果固化 | 进度总览 |
| **存放位置** | AiWork/ | AiWork/{年月}/ | AiWork/{年月}/ | docs/ | AiWork/Work.md |
| **维护方式** | 单文档持续更新 | 归档固化 | 多文档归档 | 独立文档固化 | 持续更新 |
| **示例** | 审查报告(未完成) | 审查报告(已完成) | 日常工作日志 | 设计文档、API文档 | Work.md |

**关键词匹配**:

**追踪文档关键词** (任一匹配 → 追踪文档):
- 审查、审核、检查、review
- 修复、修正、修复总结
- 开发记录、开发日志
- 问题分析、问题排查、问题追踪
- 临时方案、临时记录

**工作日志关键词** (任一匹配 → 工作日志):
- 工作日志、日报、日志
- 决策记录、临时事项
- 日常工作、会议记录

**成果文档关键词** (任一匹配 → 成果文档):
- 设计、方案、架构
- API、接口、REST
- 数据库、database、schema
- 模型、models
- 服务、services
- 枚举、enums
- 事件、events
- 配置、config
- README、概览

**进度总览关键词**:
- Work.md (固定文件名)

---

### 步骤1.5: 判断任务状态(仅追踪文档)

**任务状态判断**:

判断追踪文档是"进行中"还是"已完成":

**判断方法**:
1. **文档内容标记**: 查看文档中的状态标记
   - ✅ 完成 → 已完成 → 归档到 `AiWork/{年月}/`
   - 🔄 进行中/待处理 → 进行中 → 放在 `AiWork/`
   
2. **询问用户**: 如果无法从文档判断
   - "任务是否已完成?"
   - "是否需要归档?"

3. **默认规则**: 创建新追踪文档时默认为"进行中"
   - 新建追踪文档 → 放在 `AiWork/`
   - 任务完成后 → 归档到 `AiWork/{年月}/`

---

### 步骤2: 命名规范验证

**追踪文档命名格式**: `{日-时分-主题}.md`

格式规则:
- **日**: 两位数字 (01-31)
- **时分**: 四位数字 (0934 = 09:34)
- **主题**: 中文优先,简洁描述 (如 "Novel审查报告", "问题分析")
- **英文备用**: 如需英文,使用小写单词 (如 "novel-review", "issue-analysis")
- **示例**:
  - 中文优先: `30-0934-Novel审查报告.md`
  - 英文备用: `30-0934-novel-review.md`

**成果文档命名格式**: `{主题}.md`

格式规则:
- **主题**: 中文优先,模块/功能名称
- **中文示例**: `模型.md`, `接口.md`, `数据库.md`, `服务.md`
- **英文备用**: `models.md`, `api.md`, `database.md`, `services.md`
- **禁止**: 时间戳、中文拼音混用

**进度总览命名**: `Work.md`
- 固定文件名,不更改
- 位置固定: `AiWork/Work.md`

**中文优先原则**:
- ✅ 优先使用中文命名 (更易理解,团队协作友好)
- ✅ 英文命名作为备选方案
- ✅ 同一项目内保持命名风格一致
- ❌ 避免中文拼音混用 (如 "moxing.md")

---

### 步骤3: 位置验证

**位置规则**:

| 文档类型 | 存放位置 | 目录特点 | 说明 |
|---------|---------|---------|------|
| **追踪文档(进行中)** | `AiWork/` | 无年月子目录 | 任务未完成 |
| **追踪文档(已完成)** | `AiWork/{年月}/` | 年月格式: 202604 | 任务完成归档 |
| **工作日志** | `AiWork/{年月}/` | 年月格式: 202604 | 按年月分类 |
| **成果文档** | `docs/{模块}/` 或 `Modules/{模块}/docs/` | 模块级目录 | 长期使用 |
| **进度总览** | `AiWork/Work.md` | 固定位置 | 持续更新 |

**重要区别**:
- 追踪文档(进行中): `AiWork/` **无年月**
- 追踪文档(已完成): `AiWork/{年月}/` **带年月**
- 工作日志: `AiWork/{年月}/` **始终带年月**

---

### 步骤4: 重复文档检查

**追踪文档唯一性检查**:

检查逻辑:
1. **检查进行中的追踪文档**: 查询 `AiWork/` 目录（无年月）
2. **检查已完成的追踪文档**: 查询 `AiWork/{年月}/` 目录
3. 搜索相同主题的追踪文档
4. 判断是否已存在追踪文档

判断标准:
- **已存在**: 文件名主题部分相同
- **已存在**: 文件内容主题相同
- **已存在**: 同一任务的不同阶段文档

处理策略:
- **进行中**: 更新现有文档,添加新章节（保持单文档原则）
- **已完成**: 任务完成,可创建新的追踪文档
- **不存在**: 创建新的追踪文档放在 `AiWork/`

**特殊场景**:
- 进行中的文档在 `AiWork/` → 不创建新文档,更新现有文档
- 已完成的文档在 `AiWork/{年月}/` → 可创建新文档开始新任务

## 文档生命周期管理

### 追踪文档生命周期

**阶段划分**:

```
创建阶段 → 创建追踪文档,记录初始状态
  ├─ 位置: AiWork/ (无年月)
  ├─ 创建文档,记录任务开始时间
  ├─ 记录问题清单/设计方案
  └─ 标记状态: 🔄 进行中

执行阶段 → 持续更新同一文档
  ├─ 位置: AiWork/ (保持无年月)
  ├─ 发现新问题 → 添加到问题清单
  ├─ 开始修复 → 添加修复章节
  ├─ 新阶段开始 → 添加新章节
  ├─ 禁止创建新的独立文档
  └─ 保持在 AiWork/ 目录

完成阶段 → 总结并标记完成,执行归档
  ├─ 添加最终成果总结
  ├─ 添加经验教训
  ├─ 标记状态: ✅ 完成
  ├─ 执行归档操作 ⭐
  └─ 移动文档: AiWork/ → AiWork/{年月}/
```

**归档操作** (任务完成后执行):

当任务标记为 ✅ 完成时,执行归档:
```
步骤1: 确认任务完成
  ├─ 查看文档状态标记
  ├─ 确认无待处理事项
  └─ 用户确认任务完成

步骤2: 计算归档年月
  ├─ 使用当前年月
  ├─ 格式: YYYYMM (如 202604)
  └─ 确保 AiWork/{年月}/ 目录存在

步骤3: 执行归档操作
  ├─ 移动文档: AiWork/{文档名}.md → AiWork/{年月}/{文档名}.md
  ├─ 示例: AiWork/30-0934-Novel审查报告.md → AiWork/202604/30-0934-Novel审查报告.md
  └─ 确认移动成功

步骤4: 更新文档记录
  ├─ 在 Work.md 中标记任务完成
  └─ 记录归档位置
```

---

### 成果文档生命周期

**阶段划分**:

```
编写阶段 → 编写内容
  ├─ 位置: docs/{模块}/
  ├─ 编写文档内容
  └─ 无需归档(位置固定)

审核阶段 → 固化前审核
  ├─ 审核文档质量
  └─ 确认文档正确

完成阶段 → 固化,不再频繁修改
  ├─ 标记文档完成
  └─ 保持在 docs/{模块}/
```

---

### 工作日志生命周期

**阶段划分**:

```
创建阶段 → 创建工作日志
  ├─ 位置: AiWork/{年月}/ (直接带年月)
  ├─ 按日期或事件创建
  └─ 无需归档(位置已分类)

记录阶段 → 持续记录日常工作
  ├─ 可多文档并存
  ├─ 按年月分类存储
  └─ 保持在 AiWork/{年月}/

完成阶段 → 不需要特殊操作
  ├─ 工作日志持续积累
  └─ 按年月自然分类
```

## 实际操作流程

### 创建新文档时

**必须执行的步骤**:

1. **分析文档性质**
   - 判断是追踪文档/成果文档/进度总览
   - 使用关键词匹配辅助判断

2. **生成正确命名**
   - 追踪文档: `{日-时分-主题}.md`
   - 成果文档: `{主题}.md`

3. **确定存放位置**
   - 追踪文档: `AiWork/{年月}/`
   - 成果文档: `docs/{模块}/`

4. **检查重复文档**
   - 查询现有追踪文档
   - 如已存在,提示更新而非创建

5. **输出决策报告**
   - 文档类型判断结果
   - 建议的命名格式
   - 建议的存放位置
   - 重复文档检查结果
   - 最终决策建议

---

### 验证现有文档时

**检查项目**:

1. **命名规范检查**
   - 文件名是否符合格式要求
   - 追踪文档是否包含时间戳
   - 成果文档是否不含时间戳

2. **位置验证**
   - 追踪文档是否在 `AiWork/{年月}/`
   - 成果文档是否在 `docs/` 或 `Modules/*/docs/`
   - Work.md 是否在 `AiWork/`

3. **重复文档检查**
   - 同一任务是否存在多份追踪文档
   - 是否违反单文档维护原则

4. **输出验证报告**
   - 合规项列表
   - 违规项列表
   - 修复建议

## 常见错误与纠正

### 错误1: 为追踪任务创建多份文档

**错误示例**:
```
AiWork/202604/
├─ 30-0934-Novel审核报告.md     # 审核阶段 ⚠️
├─ 30-1030-Novel修复总结.md     # 修复阶段 ⚠️ 违规
└─ 30-1100-Novel修正报告.md     # 修正阶段 ⚠️ 违规
```

**正确做法**:
```
AiWork/202604/
└─ 30-0934-Novel审查报告.md     # 单文档追踪 ✅
   ├─ 第1节: 审核阶段
   ├─ 第2节: 修复阶段 ← 同一文档
   └─ 第3节: 修正阶段 ← 同一文档
```

**纠正策略**:
- 识别重复的追踪文档
- 合并到一份文档
- 删除多余文档
- 添加章节标记各阶段

---

### 错误2: 追踪文档命名缺少时间戳

**错误示例**:
```
docs/Novel审查报告.md     ⚠️ 缺少时间戳,位置错误
```

**正确做法**:
```
AiWork/202604/30-0934-Novel审查报告.md     ✅
```

**纠正策略**:
- 添加时间戳
- 移动到正确位置

---

### 错误3: 成果文档包含时间戳

**错误示例**:
```
docs/Novel/30-0934-models.md     ⚠️ 不应有时间戳
```

**正确做法**:
```
docs/Novel/models.md     ✅
```

**纠正策略**:
- 移除时间戳
- 使用主题命名

---

### 错误4: 位置错误

**错误示例**:
```
docs/30-0934-Novel审查报告.md     ⚠️ 追踪文档不应在 docs/
AiWork/models.md                  ⚠️ 成果文档不应在 AiWork/
```

**正确做法**:
```
AiWork/202604/30-0934-Novel审查报告.md     ✅
docs/Novel/models.md                       ✅
```

## 特殊场景处理

### 场景1: 不确定文档性质

**处理策略**:
1. 优先询问用户
2. 默认判断为成果文档(更保守)
3. 提示用户可后续移动

---

### 场景2: 跨模块文档

**处理策略**:
- 项目级文档: `docs/`
- 模块级文档: `Modules/{模块}/docs/`

---

### 场景3: 临时查看文档

**处理策略**:
- 不创建文档
- 直接在对话中输出
- 或保存到临时位置

## 注意事项

1. **必须使用此技能**: 创建文档前必须激活此技能
2. **单文档维护**: 追踪类任务严格遵守单文档原则
3. **命名规范**: 严格遵守命名格式要求
4. **位置正确**: 确保文档存放在正确位置
5. **防止重复**: 检查并避免创建重复追踪文档
